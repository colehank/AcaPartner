# AcaPartner 产品设计上下文

本页是产品上下文的唯一正文。领域词义见[词表](glossary.md)，操作说明见[工作台指南](../workbench-guide.md)，当前工程接入见[文稿与工作台](../architecture/document-adapters.md)。目标系统的分解和迁移见[架构提案](../architecture/system-architecture-proposal.md)。

本文件为 GUI 与 Design System 工作提供产品上下文。依据本轮用户讨论及《AcaPartner 科研 AI 原生产品创业企划书》v0.1（2026 年 10 月 23 日修订）整理。这里分别记录产品方向、拟议首期范围与现有实现，供后续设计判断使用；具体工程合同查阅当前架构记录与代码。

## Platform

web

当前通过桌面浏览器使用本地或自托管的科研工作桌。需考虑浏览器与科研计算环境位于不同机器的情况，包括 Windows 浏览器访问 Linux 计算环境。

借鉴 Apple 的 UX 原则是已确定的设计方向，不意味着改为原生 macOS 应用。原生客户端、移动端和机构部署的具体范围尚未确定。

## Users

企划书将认知神经科学中的数据密集型实证研究作为首期切口。

- 日常使用者：直接参与研究工作的一线研究者，不以学位、职称或职业阶段限定。他们持续处理研究问题、实验记录、数据、代码、结果、图与稿件，需要理解、审查和直接修改成果，也需要把具体工作交给 Agent。
- 审阅与采购相关者：PI 或课题负责人，关注证据、团队进展、知识移交以及真实的质量和效率改善。
- 方法与技术支持者：维护公共分析方法和计算环境，希望复用已有资产，减少逐项目适配与救场。

以上是工作中的角色，同一人可以同时参与研究、审阅、方法维护和采购决定。用户能力与界面权限应依据实际工作及授权，而不是学位、职称或身份标签。

企划书建议优先接入已有数据、分析脚本与阶段成果，仍持续补数据、比较解释和修改图稿的小型研究团队。目标用户不以会编程或不会编程作统一假设；具体熟练程度需由真实设计伙伴验证。

## Product Purpose

AcaPartner 是人与 Agent 围绕同一项目持续工作的科研 IDE。用户将其概括为交付系统与委托系统，类似普通 IDE 的编辑器与执行器；企划书使用交互系统、托付系统与共享项目枢纽说明其职责。

研究者记录观察、形成问题、检查证据、直接修改图文，并决定关键科学取舍；Agent 接收委托，承担调查、分析、制图、返修和项目接续。双方操作共同的科研对象，使每轮认识和素材能够进入下一轮研究以及论文、演示和海报。

首要价值是降低持续科研中的人工净负担，包括重复介绍上下文、寻找依据、搬运文件、审查纠错、返工与整理。科学讨论、探索和现实实验本身的投入需分别理解，不能简单等同于应被消除的时间。

成功的协作应让研究者能依据实际成果继续研究，或作出有依据的暂停、收缩和停止决定。阴性结果或暂时无法区分解释，也可以是有价值的交付。

## Positioning

拟验证的产品差异是：在持续变化的实证项目中，把问题、实验身份与科学选择、数据、方法、实际运行、证据和多种成果保持为可理解、可编辑、可接续的共同工作对象。

关键体验包括：研究者直接修改图文后仍能继续生成；数据或筛选变化后能理解影响并更新必要部分；同一结果可用于多种表达；换会话或换人后仍能继续工作。

上述差异是需要与现有工具组合及可接入科研工作台比较的产品假设，尚未证明市场领先、外部留存、付费需求或效率提升。独立工作台与现有平台上的领域协作层，仍是企划书保留的路线选择。

## Operating Context

研究工作在问题、笔记、实验记录、数据、脚本、结果、图与文字之间往返。用户可以从任一已有内容进入，逐渐补齐执行所需信息。

用户明确的两种主要起点是：带着一个尚未明确的 idea 开始，或带着已经做了一半的研究继续。后者可能已经有数据、记录、脚本、结果和稿件，不应被要求从空白项目重新填写研究结构；前者也不以已有明确 Q 或完整 QAEC 为前提。两者都需要让搭档理解当前研究，并围绕眼前的未知继续工作。

项目长期存在，数据会补录，排除规则和方法会变化，图稿会经历多轮手工编辑与 Agent 返修。浏览器关闭或会话切换之后，应能找回工作位置、当前认识、实际进展、受阻事项与待审修改。

用户已确认两种 Agent 合作方式并存：围绕当前内容随时讨论与局部协作，也可以把较完整的工作交出去，在后台推进后再审阅。讨论与委托共用项目内容和上下文，不能成为彼此隔离的两套工作空间。用户已确认：进入项目先理解已有研究、当前认识和下一步；右侧共用一个输入，由搭档理解讨论或具体工作意图，返回实际回复或可审阅建议，不要求先选择模式。用户已选定三栏工作区：左侧为类似 VS Code 目录树的项目导航，中间呈现选中内容，右侧为 Agent。侧栏可收起，中央保持直接阅读与编辑；其具体尺寸与状态通过实际工作台验证。

企划书提出的首期验证链路：

1. 从已有成果进入笔记，记录观察、问题和替代解释。
2. Agent 检查项目已有材料，整理有范围、输入、交付与停止条件的委托。
3. 在一个 session 或小批代表数据上运行，形成结果、可编辑图与必要说明。
4. 研究者直接修改或整理一轮意见；Agent 在对应版本上返修。
5. 按约定扩展数据范围，或在补数据、排除批次后检查影响并局部重算。
6. 保留适用的人工布局，检查图文解释，并将同源结果用于其他成果。
7. 导出可携带核心包，由另一位研究者在声明的依赖条件下继续工作。

QAEC（Question、Analysis、Evidence、Conclusion）帮助组织问题、分析、证据与阶段认识，不是每个问题必须填满的四个槽位。当前研究图以项目为唯一根入口，页头项目名提供上下文，画布不重复绘制根 Q，后端根对象仍保留；Q 分为父问题与叶问题：父 Q 有有效子 Q，只组织子问题，不直接连接分析或回答结论；叶 Q 承载 A/E/C，可引出多条 A。综合判断放入最后一个明确的叶子 Q。A/E/C 各自具有独立身份、正文、进度和版本。每项 A 最多产生一项可版本化 E，多项 E 可以共同支持、限制或反驳 C，C 再明确回答叶 Q。父 Q 完成依赖全部直接子 Q，并需独立核对说明与足以共同作答的确认，不因子 Q 全部完成而自动完成。问题拆解、科学关系和 Q 之间的前置条件分别表达。总体研究问题仍可作为研究内容保留，项目根不强制展开额外一行 QAEC。背景单独记录已有认识、来源和问题形成过程；自由笔记、不完整问题与尚无结果的分析均可先保留。具体模型见[自由研究图](../research-workflow/free-research-graph.md)。


## Capabilities and Constraints

### 已确定的设计方向

- 从头设计 GUI 与 Design System，通过真实使用逐步优化交互和功能。
- 以 Apple 的 UX 原则指导取舍，重视目的、用户自主权、熟悉感、清晰层级、及时反馈、恢复能力和长时间工作的舒适性。
- 人与 Agent 围绕同一项目工作；科研内容、来源和修改需要保持共同身份。
- Git 是本轮讨论认可的版本协作方向。项目文件组织、提交策略、分支与工作区、数据库分工、迁移和大型数据管理仍需工程设计；不能把这一方向写成当前已经实现的能力。

### 企划书提出的首期范围

- 优先使用神经电生理项目中已有的结构化派生数据、预测结果和分析脚本。
- 先支持一个主要研究者与受约束的多个 Agent，复用现有计算环境。
- 以一条真实分析链和有限素材类型收束范围，贯通委托、编辑、返修、更新与交接。
- 主要成果是可编辑研究报告或论文草稿与科研图，同时验证同源结果向汇报或海报用途复用。
- 原始数据通常保留在既有存储，记录可访问位置、内容身份和实际分析选择；首次接入不要求迁移全部历史材料。
- 优先复用已有方法与成熟工具；执行后端和领域适配按实际缺口选择。

### 产品工作规则

- 每类内容有明确的权威来源；目录、视图、文件位置和对象身份分别管理。
- 笔记与实验记录允许不完整草稿。执行确实依赖某项信息时，再检查其存在性与科学含义。
- 方法定义、实际运行、成果组装和证据支持关系保持可区分；生成成功不能代替科学判断。
- Agent 基于明确输入与版本工作；候选不能覆盖后来的人工作业。纯样式修改应避免无必要的科学重算。
- 委托范围与预算可以覆盖常规执行。重要科学分叉、范围扩大与重大支出需要清楚的决策入口。
- 项目内记忆、经过比较的 harness 改进和基础模型训练是不同用途。模型训练不作为普通使用的默认条件。

### 当前仓库的实现事实

首页和论文直达入口共用统一科研工作台。真实项目的研究 Q/QAEC、背景、文件、笔记、委托与任务读取沿用 Store 和既有接口。DOCX 使用 SuperDoc，LaTeX 独立保存并编译，保存不隐式切换主源；草稿、版本冲突和 Agent 本机工作副本提交均有保护。旧版工作桌、独立编辑器试用页与演示原型已移除。

项目概览以保存版当前认识和自由研究图为中心，保留原有中性 Apple / VS Code 式 IDE 外壳。新进入首页时优先打开记住且当前可见的项目，没有可用记录时选择最近更新的可见项目；切换项目先到研究图，浏览器刷新保留工作标签与草稿。项目标题提供根上下文，画布不重复绘制项目根 Q，后端根对象仍保留；原总体 Q 从“项目内容”抽屉进入原有记录与历史。旧项目通过“导入研究图”明确迁移，保留 Q 身份、原 QAEC 正文及历史、论文、材料与笔记；空槽不生成虚构结果，父 Q 的已有 AEC 自动整理到末尾子 Q；仅曾经认证且满足新依赖的完成记录可转移，不从文字或结构调整推断完成。

画布标明“最新版本”，节点以内容卡片显示编号、状态、标题和保存内容摘录；E可显示保留列名与分母的结果表节选，缩远时逐级隐藏摘录以保持结构可读。点击卡片主体读完整详情，独立箭头展开或收起分支，卡片宽高和路由不随缩放改变。A/E/C 随所属叶 Q 编号：本例 Q1.3 的并行路线为 A1.3-1/E1.3-1、A1.3-2/E1.3-2，汇总结论为 C1.3；Q1.1 的单一路线为 A1.1/E1.1/C1.1。编号只是读取投影，不改变对象身份、正文、修订或状态。桌面和手机使用同一从左向右的连续画布；已完成 Q 初次收起，未完成 Q 初次展开，手动展开选择和镜头按项目记住。点击父Q卡片的独立箭头展开或收起子Q，点击叶Q箭头展开或收起已有AEC；点击卡片主体只选中并阅读详情；选择 A/E/C 读取详情及直接关联，不切换子图。初始镜头优先保留可读的顶层 Q，屏外内容通过平移、缩放、明确聚焦或查看全局阅读；返回上一视角恢复此前明确动作的镜头与展开快照，重置可恢复默认折叠。下部覆盖检查器不缩小画布或自动重置镜头；树与搜索显露祖先并在图内定位，原有记录由明确入口打开。淡色分区框表达问题归属，顶层 Q 同列、分支按编号排列，展开的综合工作位于可见前置工作之后；父子层级为灰色无箭头正交线，定向依赖已兑现为实线，待推进为虚线。折叠端点的关系投影到可见 Q 边界，多条同向同端点关系可汇总显示，并保留真实关系选择及实际端点；只有全部真实关系已兑现才显示为已兑现。这些投影不新增研究关系或归属，连线本身不等于科学支持证明。节点详情提供正文、“编辑与状态”、具名完成依据、来源和只读历史。切换节点、关闭详情或项目切换后，晚到的历史结果不能进入新选择；历史不改变主图。

节点保留待开展、进行中、待确认、已完成与暂缓，兼容未标记旧记录。确认完成需要具体标题、非空正文、核对说明和准确依赖签名；确认绑定保存内容、问题范围与关系版本，并通过不可变记录核验。E 需要唯一产生它的 A 完成，C 需要明确关联的 E 完成，叶 Q 需要回答它的 C 及所声明前置 Q 完成；父 Q 需要全部直接子 Q 及所声明前置 Q 完成，且不能直接拥有 A 或回答 C。两类 Q 均需独立核对说明、准确依赖签名和足以作答的明确确认；阴性结果也可以回答。叶 Q→A 绑定分析范围，不要求 Q 先完成；父→子 `contains` 的完成签名反向绑定子 Q→父 Q，子问题变化可逐层使父确认待复核；完成依赖和问题拆解分别拒绝循环，允许研究语义上的 Q→A→E→C→Q 回指。内容、来源、问题范围、关系或依赖签名变化会使原确认及下游待复核；恢复旧文字仍需重新确认。人工记录与旧确认保留，不自动改写结论，也不按填满节点计算完成率。

父 Q 的新建入口仅提供子 Q；已有 AEC 的叶 Q 新建子 Q 时，通过原子“拆分并迁移”将原 A/E/C 接入新叶 Q，保留对象身份、正文、历史及撤回的关系记录，改变范围后重新核对完成。旧混合结构仍可读取并整理，不能确认完成或新增混合关系；侧栏及旧创建入口也不能绕过这一规则。

图节点的新建、修改、关联和来源登记使用 [`workbench.graph.*`](../research-workflow/research-graph-api.md)，复用 Store、`graph_growth` 关系历史、项目权限、CAS 与稳定请求键；布局复用本地 Graphviz 与 React Flow，技术边界见[布局接入](../architecture/research-graph-layout.md)。授权 Agent 可使用相同 API 读写图，但不能自行确认科学完成。

右侧统一输入现已通过 `research.partner.preview/submit` 的 `graph_mode:"edit"` 接入独立图变更合同。每轮读取冻结的最新图摘要、选中节点的准确保存正文和明确选择的材料；发送后仍由已有有限 Runtime、提供者、预算与回执机制执行。有效变更原子保存并自动刷新画布，无需再进入问题提案采用页；普通讨论可以不改图。新 Q/A 为待开展，E/C 只能整理本轮原话或选定保存材料中有逐字依据的报告内容，保留准确来源并待确认，不填造实验结果，不执行脚本、修改文件或确认科学完成。每条消息另保留不可编辑的用户输入来源。

选中图节点后，其编号与标题贴近输入显示，后续工作仍核对冻结图与当前图。已有节点的稳定身份和无关内容保留；并发变化时，回复与候选保留但不覆盖当前图。回复内显示已应用、未应用或已撤销的回执，并可查看画布、按当前图继续或整轮撤销。撤销需研究者操作，核对应用后的整图版本；通过归档新节点、撤回新关系和将原内容另存新修订保留历史，后续工作存在时拒绝覆盖，也不恢复旧科学确认的有效性。具体事务边界见[搭档图变更接入](../architecture/partner-graph-changes.md)。

省略 `graph_mode` 的旧 `research.partner.*` 任务及 `research.work.*` 仍使用每 Q 一组 QAEC 的候选与明确采用，尚未自动映射到独立多 A 图。旧 QAEC 须明确“导入研究图”后才可接受搭档自动图变更；原编辑器和记录继续保留，独立 A/E/C 不隐式双向覆盖。图变更支持增量节点和关系，不支持模型删除、重新归属已有 Q 或自动拆分已有 AEC 叶 Q；整理仍走明确的整理操作。页面载入不调用模型或写入研究内容。

图节点的新建与编辑输入按项目、浏览器窗口和节点保留本地草稿；切换选择、关闭详情、取消或刷新后可从“草稿”入口继续、下载或明确删除。保存核对项目与节点基础版本，冲突保留输入；本地存储失败时明确提示下载正文。

右栏已支持逐轮有限讨论与图变更；自动多轮自主科研、SSH 执行/监控、完整科研 Harness、任意多服务端文稿、格式互转和多人实时协作尚未完成。已存在的后台工具或字段不等于当前界面可用或科学质量已验收。

## Brand Commitments

AcaPartner 为当前产品工作名，仓库亦沿用 Research Partner 名称。

用户明确指定 Apple 的 UX 原则作为设计参考，同时不要求复制 Xcode 的具体体验。2026 年 10 月 26 日，在三栏结构原型之后，用户要求调研 Linear 与 Craft 并授权视觉修订：工作台秩序参考 Linear，文档阅读与编辑体验参考 Craft。独立原型 v0.2 据此实现中性明暗主题、紧凑工具区和独立的文档排版；具体样式仍需通过使用反馈迭代，不视为已有正式品牌资产。

## Product Principles

1. **围绕研究内容工作。** 从问题、笔记、图和稿件进入，减少重复描述上下文与搬运素材的负担。
2. **共同维护一个项目。** 人工编辑、Agent 动作与实际运行使用可对应的对象、版本和来源。
3. **支持自主探索与接手。** 保留手改、可恢复状态与明确范围，让研究者理解变化并掌握关键科学判断。
4. **让结果及其限制可检查。** 区分计划、执行、证据和解释；及时交付当前有用的认识，包括失败、阴性和未决事项。
5. **用真实使用推动演化。** 先验证有限科研链路，观察人工净负担、质量与接续，再扩展功能；按需调用能力并减少无益步骤。
6. **优先复用成熟实现。** 用户明确要求所有开发避免重复建设通用能力。先检查仓库已有实现与维护中的依赖，通过适配连接科研工作流；Office、LaTeX、PDF、编辑器等采用成熟引擎，并核实其实际支持范围、授权与部署条件。

## Mandatory Manuscript and Status Bar — 2026-10-28

用户确认交付系统默认必须有一项论文，项目不以没有任何交付物的状态开始。论文可以采用 DOCX 或 LaTeX，两种格式都需要有实际源文件的渲染和编辑能力；它们是同一论文交付类型的不同格式，不自动生成两份需要分别维护的论文。演示文稿、海报等仍可按需要加入。论文组织本项目的研究对象，不限制研究问题数量，也不因交付编辑而改写研究结论。

底栏内容固定为三组：左侧仅服务连接状态；中间仅当前内容地址；右侧依次为 Token 消耗、设置、明暗切换。保存与草稿反馈归属当前内容工具区和辅助技术状态播报，不占用底栏。地址跟随当前项目、内容、问题分面或全局页面更新，窄屏省略显示并保留完整地址。

当前项目默认创建论文交付。首次打开时选择 DOCX 或 LaTeX 源稿；两种源文件独立保存，打开和保存均不隐式互转或替换论文绑定。具体编辑、审阅、编译和版本保护范围见[文稿适配](../architecture/document-adapters.md)。

## Accessibility & Inclusion

既有需求包含中文输入、长文阅读、精确选择、键盘操作和可调整工作区域。设计与验证需覆盖中文与英文混排、公式和科学符号、长文件名、窄面板以及真实浏览器条件。

具体可访问性标准、辅助技术覆盖范围和目标硬件尚未确定，后续需明确并验证，不能宣称当前已符合某一标准。
