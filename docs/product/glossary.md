# AcaPartner 领域词表

记录当前讨论中明确的领域词义。产品文档入口见 [docs/product](README.md)，具体工作规则和未决设计见[工作流推演](../research-workflow/README.md)；词表不代表相关功能已经实现。

## Language

**研究意图**：
研究者希望探索的方向、观察、困惑或目标，可以模糊，也可以已经接近一个具体问题。它是讨论和工作的起点，允许在进一步了解材料后改变。
_Avoid_: 把最初的一句话直接当作已确定的研究问题，或要求已有明确 Q 才能开始协作。

**研究问题提案**：
对值得研究的未知所提出的候选表述，连同形成理由、依据或假设、可能的分析路线和需要的证据。可经讨论改写、暂存或采用；采用为项目 Q 表示选择当前研究方向，不代表已有答案或科学确认。
_Avoid_: 将澄清目标的待决事项当成研究问题提案，或用问题提案预先填造证据和结论。

**研究问题（Q，Question）**：
研究中希望澄清的未知，具有可逐步明确的范围和提出缘由。问题可以并列、继续拆解。当前自由图中，父问题组织子问题，叶问题承载分析、证据与阶段回答。
_Avoid_: 用执行任务或等待用户答复的事项代指研究问题。

**父问题 / 叶问题**：
有有效直接子 Q 的问题是父 Q，只组织子 Q，不直接拥有分析关系（`analyzes`）或回答结论（`answers`）；没有子 Q 的问题是叶 Q，可承载一条或多条 A/E/C 路线。需要综合判断时，将其作为最后一个明确的叶子 Q。角色由当前有效问题结构派生，不按标题或编号猜测。
_Avoid_: 让同一个 Q 同时直接拥有子问题和自己的 AEC，或把所有子问题完成当成父问题自动完成。

**研究图根节点**：
当前项目或整体研究主题的入口，并连接多个研究问题。后端保留项目根对象；当前画布由页头项目名提供上下文，不重复绘制根 Q。具体研究问题保留自身的科学表述，根节点不强制展开成另一整行 QAEC；原总体问题从“项目内容”中的原有研究记录与历史读取。
_Avoid_: 用项目名替代具体研究问题的含义，或把根节点当作必填的额外 QAEC 套件。

**论文研究问题**：
一篇论文希望回答的总体研究问题，可通过多个子问题展开，并由分析、证据与结论逐步作答。它组织这篇论文的研究论证，不等于稿件文件，也不限制整个项目只能有一个研究问题。
_Avoid_: 用论文标题或稿件完成状态代替研究问题及其判断。

**问题完成**：
研究问题已有足以作答的结论，阴性结果也可以构成回答；叶 Q 需对应回答结论完成；父 Q 需全部直接子 Q 完成，不另有直接回答 C。两类 Q 都需要独立核对说明、准确依赖签名，以及足以回答该问题的明确确认；所声明的前置 Q 也必须完成。当前确认绑定准确保存内容与依赖版本；证据不足以回答时，问题保持未完成或明确暂缓。
_Avoid_: 将阶段工作收束、结论文字已保存或任务结束等同于问题已得到回答。

**节点进度与完成确认**：
每项问题、分析、证据和结论具有自己的名称、内容和进度；叶问题可以引出多项分析，每项分析最多产生一项可版本化的证据结果，多个证据可共同形成结论。完成确认说明核对依据，并绑定内容、研究范围与所声明依赖；问题完成还需确认结论足以回答问题。
_Avoid_: 将完成确认解释为模型审批、自动科学验证，或将 E 完成到 C 的固定条件解释为已建立科学支持关系。

**完成依赖与待复核**：
当前自由图按类型建立关系：A 产生 E（`produces`），E 支持、限制或反驳 C（`supports/limits/refutes`），C 回答 Q（`answers`），前置 Q 约束后续 Q（`prerequisite`）；这些关系的来源须完成并保持确认版本。父 Q→子 Q 的拆解（`contains`）在完成核对中绑定反向的子 Q→父 Q 签名，父 Q 必须逐项核对全部直接子 Q；项目根包含不产生这一完成要求。叶 Q 开展 A（`analyzes`）绑定分析范围，不要求 Q 先完成。完成依赖与问题拆解分别保持无环；研究语义允许 Q→A→E→C→Q 回指。内容、标题、来源、范围、关系及依赖签名变化使当前确认和下游待复核，旧进度、正文与确认保留；恢复旧文字不恢复旧确认。
_Avoid_: 用层级或连线自动推断科学支持，或把受阻、待复核当作覆盖人工进度的手工状态。

**分析（A，Analysis）**：
为回答研究问题而进行的推理、比较、建模、检验或综合，以及相应的方法与条件。同一叶问题可以有多条分析路线，一项分析也可以服务多个叶问题；父问题不直接拥有分析。
_Avoid_: 将 A 解释为 Answer，或把所有 Agent 动作都称为分析。

**证据（E，Evidence）**：
用于支持、限制或反驳某个研究判断的观察、结果或来源，连同其相关性、适用范围和解释依据。
_Avoid_: 因为结果文件存在，就认定它支持某个结论。

**结论（C，Conclusion）**：
依据当前证据对研究问题作出的阶段回答，包含适用条件和仍未解决的部分。C 明确回答叶 Q。父问题的综合判断放入末尾叶子 Q，父 Q 自身保留问题正文和独立的完成核对，不直接拥有回答 C；原 QAEC 历史中的父结论继续保留为原记录。
_Avoid_: 把任务完成、内容被采用或肯定性结果等同于结论成立。

**背景**：
项目采用的已有认识及其来源，以及研究问题如何从这些认识、观察或矛盾中形成的说明。
_Avoid_: 将背景主题直接当成待回答的研究问题。

**研究材料**：
研究中使用的数据、文献、原始记录、笔记等输入内容。材料可以先自由保存，再逐步建立与问题和工作的关系。
_Avoid_: 将某个问题的分析与结论一并堆入材料分类。

**结果**：
一项研究工作产生的具体观察、数值、图表、推导或其他产物。结果在具体论证中被解释和引用，形成针对某个判断的证据。
_Avoid_: 将结果与结论混用。

**研究任务**：
为了推进研究中的具体缺口而开展的一项有范围的工作，具有输入、预期产物和完成或停止条件。一个研究问题可以经历多项任务。
_Avoid_: 把研究问题本身当成一次可直接执行完毕的任务。

**委托**：
研究者把一项工作交给 Agent 或协作者时，对目标、范围、产物及自主行动边界的约定。
_Avoid_: 将讨论中的建议自动视为已经交出的工作。

**研究修改候选**：
围绕明确研究问题形成的分析、证据或结论修改建议，包含建议内容、修改理由、依据和限制。研究者可比较、改写并采用其中一部分；未采用内容仍可保留。
_Avoid_: 把任务返回的候选当成已保存的研究认识，或把采用等同于科学确认。

**搭档图变更**：
研究者发送一轮消息后，搭档基于冻结的当前图提出的成批节点、正文和具名关系变化。当前 GUI 经服务校验后原子保存，并直接刷新画布，不再经过问题提案采用页。新 Q/A 为待开展；新 E/C 必须有本轮用户原话或选定保存材料的逐字依据，保持待确认。保存结构、完成模型任务和确认科学判断分别记录。
_Avoid_: 将直接保存理解为模型可以制造结果、自行确认科学完成或覆盖后来的工作；也不将它与旧 QAEC 候选的明确采用合同混用。

**执行记录**：
一次实际工作尝试及其输入、方法、产物、检查和结束情况的记录。同一项任务可以拥有多次执行记录。
_Avoid_: 用预先计划冒充实际发生的过程，或用最后一次成功抹去先前尝试。

**待决事项**：
当前工作需要作出的具体选择，带有相关背景、可选方向及其后果。它可以影响工作如何继续，但不等同于科学研究问题。
_Avoid_: 与研究问题共用含混的“问题”称呼。

**交付物**：
面向特定读者或用途组织研究内容形成的稿件、报告、演示等表达。多种交付物可以引用同一研究内容，同时保留各自的结构和文字。
_Avoid_: 将交付物视为研究结论与依据的唯一存放位置。

**论文（Manuscript）**：
面向学术论证和交流组织研究问题、方法、证据与讨论的交付物，是项目默认必须保留的一类交付。DOCX 与 LaTeX 是其可采用的文稿格式，论文编辑与研究判断分别维护。
_Avoid_: 将导出的 PDF 等同于可编辑论文源稿，或将论文正文作为全部研究状态的唯一记录。

**论文源稿（Primary manuscript source）**：
论文当前采用的一份可编辑源稿。DOCX 文件与 LaTeX 源稿分别保存内容；打开论文时自动进入所绑定源稿的编辑器。保存另一份稿件不改变绑定，只有明确的“设为论文源稿”操作才重新选择。
_Avoid_: 将 DOCX 与 LaTeX 显示成同一内容的两种可随时切换的视图，或将保存等同于格式转换。


## 当前工作台投影

统一工作台主图目前使用[独立研究图](../research-workflow/free-research-graph.md)：项目为唯一根，Q 继续使用 `research_question_v1` 的既有身份，A/E/C 保存为 `research_node_v2` 独立 concept，语义关系复用 `graph_growth`。父 Q 不直接拥有 AEC；A/E/C 随所属叶 Q 形成展示编号：本例综合叶 Q1.3 的并行 A 为 A1.3-1、A1.3-2，对应 E1.3-1、E1.3-2，汇入 C1.3；Q1.1 的单一路线为 A1.1/E1.1/C1.1。编号是只读投影，不改变稳定 ID、正文、修订或状态；一叶 Q 可有多个 A，每 A 最多一项 E，多 E 可汇入 C，原总体 Q 仍可从“项目内容”中的原有研究记录与历史访问。迁移保留原 QAEC 正文与历史，父问题原 AEC 接入末尾叶 Q，空槽不创建节点；整理保留 A/E/C 身份、正文和关系历史，改变范围后需要重新核对。原编辑器继续供查阅。

当前 [`workbench.graph.*` API](../research-workflow/research-graph-api.md)支持人和已授权 Agent 读取、创建、编辑、连接节点及登记准确来源；Agent 不因写权限或读取确认记录而获得科学完成确认权。GUI 搭档发送使用 `research.partner.*` 的 `graph_mode:"edit"`，由现有有限 Runtime 执行图变更合同；冲突时保留回复与未应用结果，整轮撤销保留历史且保护后续工作。省略 `graph_mode` 的旧搭档任务及 `research.work.*` 仍使用每 Q 一组 QAEC 的候选与采用，不自动映射到独立多 A 图。背景单独保存，任务运行中的 question 继续表示等待决策的事项；这不是完整自主科研系统。
