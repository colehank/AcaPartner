# 验收场景

本文件规定产品的操作验收。S01–S24 及 S06、S07 的全部子场景都是必需；通过一个样例不能代替完整覆盖。场景可以共用真实材料与操作记录，但须逐项指明支持的能力，不能反复复制同一张截图。全部测试指向最终实际交付的构建；早期局部通过在整合后须回归。

每项保留实际输入、执行入口与记录、结果及其来源、检查方法、运行实现、失败与限制。真实用户确认、开发者操作、工具验证和科学审查分别标记。正式能力验收不使用假后端、假模型、预置成功结果或模板冒充执行；故障注入是允许的真实测试手段，但注入样例本身不作为科研成果。

## S01｜真实客户端进入和操作

在用户实际使用的客户端，从提供的安装／访问入口进入项目，打开当前成果，保存修改并重开；显示的能力、任务状态与运行实现真实对应。另测服务器入口，二者分开记录。必须诊断并解决实际访问问题或明确仍受阻；仅服务器截图或本地浏览器成功不算用户侧通过。

## S02｜多项目图谱、命名与检索

使用两个有真实资料、且获准访问的相关项目，从核心概念分域展开到问题和成果；标题、别名及标识检索到同一对象。完成新任务后节点增长；改名、归档、恢复、合并重复节点后原引用有效，已有位置可找回；没有根据的关联为候选。第二项目可来自公开真实研究，但不能被写成用户真实协作已验证。测试跨项目权限拒绝；人工维护一个静态网络不算通过。

## S03｜独立委托与研究叙事

让没有旧聊天上下文的接收者／新 Agent 仅凭交接文档与可访问附件，说明背景、当前问题、已有探索、材料、约束、预期产出和判定方式。分别检查调研报告、分析报告与研讨笔记的问题—分析—证据—断言链。调研应充分说明相关研究；分析应聚焦直接相关文献；研讨保留逻辑转折。必要信息只藏在聊天或失效本机路径中即不通过。

## S04｜同一文稿共同编辑与批注

用户编辑一段正文并批注另一段，保存刷新后文字和定位保留；明确点击请求 Agent 修订，查看真实接收、排队和执行，比较实际差异。Agent 执行期间再编辑，验证合并或冲突提示；移动／删除段落后批注不悄悄错配。恢复历史内容不删除反馈记录。断开模型或取消修订时，用户内容仍在且状态真实。仅“反馈已保存”或另存无关联文稿不通过。

## S05｜科研图修改、重放与主图

打开一张有真实脚本和数据的统计图，修改图例位置、字号、线型或标签；保存重开、恢复和导出。以另一份授权真实输入重绘，检查视觉修改重放；对象消失时定位失败项，不偷偷丢弃。把多张子图对齐组成主图，维护图号、图注及方法／结果段落来源。核对数值未因视觉编辑而改变，画面与导出一致；仅移动整张位图不通过。

## S06｜论文、海报和汇报分别完成

三个子场景均必做，源图更新时分别验证影响定位与接纳／保留旧版，不允许用一种导出替代另一种。

| 子场景 | 实际操作与最低交付 |
|---|---|
| **论文** | 从真实主题段落、主图和证据形成前言、方法、结果、讨论与引用；正文与图可来回定位、编辑和批注。实际编译并检查 LaTeX＋BibTeX＋PDF；另可导出 DOCX 内容稿。检查数字、图号、引用及手工修改保留，不保证任意期刊模板无损转换 |
| **海报** | 按用户尺寸（未指定测试可用 80×120 cm）编辑文字、图和版面，对齐／分组／调整对象；交付可重新编辑的完整源与按实际尺寸导出的矢量 PDF，实际打开检查溢出、字号、线粗和阅读顺序 |
| **PPT 与逐页讲稿** | 编辑、重排和增删页面，讲稿保持逐页关联；交付可编辑 PPTX、阅读 PDF、逐页 Markdown／文本讲稿并写入可用的讲者备注。实际打开并修改文本／对象，不能整页截图冒充可编辑幻灯片 |

图可按其实际类型保留矢量图或合适位图，不能把科学图片强行声称全部矢量；可编辑的要求针对可编辑源和受支持对象。源内容与已导出快照都可定位。

## S07｜研究工坊五类任务分别可用

共同运行器可以复用，下表五项必须各有实际执行记录和产物；同一脚本空跑不能代替。

| 子场景 | 实际输入、操作与检查 |
|---|---|
| **刺激准备** | 真实获准图像的小批量整理／变换；检查尺寸、顺序、参数、清单和预览，原素材不覆盖 |
| **图像与标注清洗** | 实际图像及标注的格式／对应关系／异常检查与受控更正；记录前后差异及不确定项，输出新的数据和标注版本 |
| **神经数据预处理** | 授权的真实神经数据小样本，完成一种明确的预处理，保存参数、输出和质量摘要；合成神经数据不作为本项正式通过依据 |
| **可视化工具** | 针对真实数据开发并启动可操作工具，执行筛选、选取或参数交互，检查显示随输入真实变化，交付代码、环境与运行办法 |
| **实验软件** | 实际运行具有刺激／输入、试次推进和事件记录的软件，用受控人工输入测试日志及状态。真实物理设备、延迟与精确时序未测即标未测，不冒充实验系统性能认证 |

用户无需进入学术工作台即可完成技术验收。对有关学术任务，能找到依赖来源、就绪状态和失败原因；技术检查失败不能被标为科研结论有效。每类支持范围要明确，但不得删掉整个类别。

## S08｜成果集合体、改名与移交

从真实成果定位必要源稿、图、文献、代码、数据、环境、参数和元信息，或实际可解析的版本化引用。改名、分类和新修订后链接、批注和组件关系仍有效。导出交接包，在另一环境检查可理解性与可执行性，缺失依赖和权限分别报告。图、方法和结果必须对应同一采用版本；只有一个指向旧主机绝对路径的清单不算可移交。

## S09｜反馈改结果，也改工作方式

保留一条真实反馈的原话、理解、候选与采用判断；当前成果修订和后续改进分别有时机与证据。Agent 主动在关键成果处征求反馈并接收中途意见，不强迫每一步批准。用后续真实相关任务比较重复解释、找错版本、纠错和成本；没有改善也可以拒绝候选，保留理由。撤回工作方式变化不损坏已产生的成果。尚无后续任务即效果待验证，不得用回忆或测试数量替代。

## S10｜独立仓库与实际可安装软件

检查新仓库有独立 Git 根、可构建源码和真实启动入口，不是旧仓库新分支或只有文档。使用干净环境执行所交付的安装步骤，运行 GUI 与独立服务／CLI；检查许可、依赖、配置样例、源码与发行物对应关系，确认无密钥和私有研究材料。开源发布准备与实际公开状态分别记录；许可文本或打包配置存在不能替代构建运行。

## S11｜开发接续与防虚假完成

开发运行器使用 C01–C50 的固定范围和实际开发状态，完成一个单元后能自动接续可执行的下一单元。人为注入：一项未实现、一项失败、一项被删除、一项被跳过、只有 mock 的验收、过时实现证据以及所有任务受外部阻塞；完成门槛必须拒绝整体完成并正确区分继续与等待。再测开发会话中断后恢复，并检验用户停止和预算耗尽不会被新会话绕过。只有提示词／状态文件而没有运行过接续过程不通过。

## S12｜科研 Agent 常驻、恢复和受控执行

发起包含真实模型与工具工作的多步骤任务，关闭客户端后从另一入口确认任务仍推进；重开观察同一任务。执行中受控终止服务并重启，恢复已提交状态，查证有副作用的步骤不重复提交；重复请求、取消、临时网络失败和达到预算上限均实际测试。进程正常退出或模型结束一轮不能自动代替任务验收；必须核对实际产物、未完成工作与错误。记录真实持续时间，不设置无依据的“整夜运行”演示指标。

## S13｜提供者与工具真实接入

在已有授权下分别通过两种模型适配路线完成同类小任务，核对实际调用身份、响应及产物；至少一路符合 DeepSeek Harness 优先路线。实际接入一项外部工具／MCP 能力并读取结果。修改配置后调用身份真正改变；撤销凭据或缺少服务时明确失败／等待，不使用模板掩盖。模型配置输入框和工具列表本身不算支持证据。凭据不足时只阻塞相关验收，继续其他开发。

## S14｜有用的协作与整合

一项真实任务拆成至少两个可独立工作的部分，各收到足够上下文和清晰产出；主 Agent 审查、指导或接手不足结果后整合。检查不会多端覆盖相同文稿，也不会把子 Agent 的“完成”直接当交付。记录分工收益、成本与限制；不要求每个任务强行并行。开发主控对最终整合负责。

## S15｜文献检索、阅读与引用

对明确范围执行真实检索或从授权库读取材料，保留来源、查询范围和可访问全文／摘要范围；读到的内容与报告中的表述对应。导入有重复和缺失字段的文献，实际去重、核对引用并导出 BibTeX；正文引用可定位原材料。无法获取全文时标清，不补造作者、DOI 或论断支持。引用数量不作为质量替代指标。

## S16｜科学质量审查能发现和修正问题

用真实报告和一份明显标识的故障注入副本，检查不支持的断言、错数、错引用、遗漏背景和仅工程成功的结论。独立审查直接查证据；问题应回到对应成果修订，不能只多生成审查报告。清楚区分结果、解释、不确定性和下一步。故障副本不进入正式科研资产，测试修复不冒充新的科研发现。

## S17｜可编辑概念图与流程图

从有出处的综述／研究框架产生节点、关系和说明，实际修改节点文本、位置、连接及分组，保存重开后导出矢量图。保留可编辑结构源，节点与说明能追溯到相关文稿。单一生成图片、不支持节点编辑，或把概念相似画成已证实因果均不通过。

## S18｜必要裁决、预算与停止确实有效

在任务中设置真实需授权的动作与普通可逆步骤；前者在授权前不能执行，后者不因无关可选讨论未答而停摆。请求裁决交代背景、选项、后果和建议。测试暂停、取消、撤回、改优先级和预算耗尽，核对执行器实际停止或保持允许的独立工作；不能只是按钮文字变了。用户中途反馈须更新有关后续任务，而非忽略或无条件改全局规则。

## S19｜升级、独立实例迁移和恢复

把含人工编辑、图覆盖、批注、引用、组件关系和任务记录的研究空间备份并迁移到另一独立实例；绑定其授权凭据并继续相关工作。升级后失败再恢复，检查内容和关系不丢、索引可重建。运行依赖不可用要标清，不要求包内带出秘密或未授权大数据。只有服务重启成功、旧研究数据仍不可用不通过。

## S20｜用户自有部署与安全边界

不依赖产品方中央登录或控制服务器，实际启动自有实例；关闭模型服务后仍能读写、检索和导出本地成果，智能执行明确报依赖不可用。验证凭据不出现在页面响应、日志、导出包或源码中；测试跨项目越权与未批准工具的拒绝。列明联网去向和外传范围，未知插件不得自带额外权限；不以“去中心化”声称所有服务离线免费。

## S21｜自有远程主机实际工作

在明确授权的第二主机／独立执行环境上运行真实轻量准备任务，检查输入、工作目录、实际进程、输出、回传、取消及连接中断；学术成果能追溯该依赖。只保存 SSH 配置或把本机任务改名为远程不通过。无凭据或主机时状态为外部阻塞，不申请不必要云费用、不拿模拟结果签收。

## S22｜功能扩展不需要重写核心

依据公开的扩展接口，在核心业务源码之外增加一个有科研用途的工具／导出器或产出能力，完成注册、发现、权限、实际调用、产物和卸载；旧项目也可使用，卸载不损坏其成果。检查领域约定和用户偏好可配置／纠正，不写死在神经科学示例中。另测扩展升级、失配报错和回退；接口占位、硬编码“插件已加载”不通过。

## S23｜成果中心的可用性

在用户实际客户端，无需阅读工程手册即可识别当前项目、当前成果和必要下一步。从项目进入当前成果原则上不超过三次导航；这是开发验收基线，确需调整时以真实用户反馈说明。正文／画布为主要区域，批注就近，日志默认展开层级不抢占工作空间。实际完成编辑、撤销、批注和导出，关键控件不遮挡且无难以使用的页面溢出。工程自测后仍需用户确认，不用截图评分替代。

## S24｜全量整合与交付检查

将同一项用户真实研究任务从委托、资料定位、执行、审查推进到可用成果，再处理真实反馈并接续后续相关任务。其他真实材料补齐论文、海报、PPT／讲稿、五类工坊、图谱、运行恢复和扩展等全部场景；用 C 清单逐项核对，不能以这一个任务覆盖尚未涉及的功能。

在最终交付构建上复验关键操作，独立审查实际产物和证据；检查当前源码、发行物和部署一致。出现未实现、失败、跳过、仅示意、外部实测受阻或用户未确认，应按 07 分别报告，不得宣告产品全部验收完成。

本节是2026-10-05用户授权的新增门槛，不取代任何旧场景或降低全量范围。

阅读渲染稿件→批字/批图（包括静态区域）→真实Agent逐条回应→分别接受/拒绝正文与准备性变化→

## 编辑细化的共同核验
