# Research Partner 产品书

**需求、解决方案与实施约定**

> 让研究者对着成果提出问题，由搭档把调查、计算、制图、修订和交付真正做完；每项结果都能找到来源，每次改变都能知道影响，每次接续都不必重建上下文。

## 使用这份产品书

第一、二章用于确认“解决什么工作问题、用户实际怎么用”；第三章给出推荐的组件组合与数据责任；第四章规定开发顺序和交付物；第五章规定如何验收。附录提供接口、目录、GitHub 拆解入口和全量能力对应关系。需求 N、场景测试 T、工作包 W、完整能力 C 和原有验收场景 S 互相定位；机器追踪见 spec/registry.yaml，用户不维护这些编号。正文及附录中的产品行为是规范依据；注册表是同一规范的工程索引，不因缺少断言而免除正文要求，也不得在正文之外静默增减需求。正文与合同冲突时暂停受影响动作，由第 4.1 节的责任主体澄清后同步二者；独立可执行工作继续。随包《验收条件索引》完整展示原子断言、工作包关口与 C/S 来源，不要求读者解析 YAML。

**依据分为三类。** 用户需求与现有实现事实来自项目材料；开源能力采用项目已有的 2026-10-08 调研记录；数据工作流和合同校验另有官方资料入口 [R22–R24]；笔记与工作桌选型依据文档、仓库及指定源码片段 [R25–R31]；组件选型、接口与交付安排属于本书的实施设计。仓库阅读不等于安装成功，更不等于已在 Research Partner 中集成。设计图片表达拟采用的界面与交互约定，不证明真实模型、计算、排版或持久化已经实现。

# 一、用户需要完成的工作

## 1.1 产品承诺与对象

科研搭档面向既有科研经验、但不愿承担工具链管理的研究者，也面向需要方法引导的研究者。科研目标是解决问题、探索未知；论文及其他科学产出是交流载体，项目同时保存未采用结果、反例、方法、计算与判断过程。

**产品是一款对象式科研工作软件，不是聊天外壳、状态看板或自动写论文网站。** 新项目直接出现可排版的论文模板；用户能在同一工作桌打开数据、笔记、代码、结果、图与稿件，直接编辑，或者把当前上下文交给搭档。没有明确课题时，先形成数据勘察和探索结果，不要求先填写文章故事。

用户承担研究意义、关键科学取舍和重要授权；Agent 承担材料调查、方法建议、具体执行、验证、组织与接续。Agent 可以基于证据反对用户的科学解释，但不能越过数据、预算、实验和发布权限。

## 1.2 必要需求：从痛点到可观察结果

| 需求 | 用户正在承受的痛点 | 产品必须交付的结果 |
|---|---|---|
| N01 数据生命周期与探索 | 数据持续补充、删减、更正；不知道能问什么，也难确认每个结果用了哪批数据 | 批次入库、分析范围快照、质量排除与恢复、完整数据计算流；有界探索与下游重做均可追查 |
| N02 项目素材管理 | 文件混乱、不同成果同源但图形不同，难查计算依据 | 稳定身份和 main/assets；共用结果、分别管理用途图；主图直接进入实际生成链及代码 |
| N03 可重复成果生成 | 计算、作图和文稿互不相通；改参数后不知道重做哪里 | 真实生成图决定运行；局部变化只重做受影响部分，完整输出与失败状态可核查 |
| N04 直接编辑科学图 | 简单视觉变化也要重新委托；手改在重绘后丢失 | 对象选择、语义分组、即时预览与可重放样式；数据变化不无声覆盖人工布局 |
| N05 自主审阅与整轮反馈 | 意见不能方便撤回或删除、逐条派任务、Agent 覆盖手改或盲从 | 用户编辑、删除、恢复、保留或不提交自己的意见；固定选定轮次后批量处理，候选可分组采用 |
| N06 项目笔记与持续协作 | 每个项目的思考、计划与日志难找，笔记依赖应用导出，后台工作难接续 | 项目独立 notes 文件库，原生 Markdown、完整导航检索和引用；后台托管、暂停恢复与任务级简报 |
| N07 表达与交付适配 | 转投、换语言、改篇幅要复制项目；预览与导出不一致 | 共享科学依据、独立表达稿和投稿配置；同一生成路径产出当前可核对的文件 |
| N08 完整科研与自主使用 | 只能做单一报告，实际准备工作和迁移仍靠人拼接 | 覆盖文献、报告、图、论文、海报、汇报、五类工坊工作；自有部署、远程与扩展可验 |

“做成了”指用户完成整项工作，不指按钮存在、返回码正确或局部检查全绿。对于未覆盖的文件格式、外部脚本与设备，入口显示支持范围；不能用模拟成功代替尚未实现的能力。

## 1.3 设计原则怎样约束代码

| 设计原则 | 必须出现的实现约束 | 用什么反例检验 |
|---|---|---|
| 对象优先，减少找入口 | 目录、画布、聊天、节点共用 object_id；所有写操作经同一命令层 | 从两种入口修改后，重开出现两份不同内容，判失败 |
| 桌面简洁，专业能力按需展开 | 继续项目默认左侧成熟成果、右侧笔记；聊天和目录可收起，用户布局记忆与内容分离 | 隐藏面板丢批注，或缩放改变图的数据范围，判失败 |
| 重复工作不再交给模型猜 | 已接受的脚本、输入和样式形成可运行定义；生成调用确定的执行器 | 没改科学条件却重写分析代码，或旧输出冒充新运行，判失败 |
| 探索灵活但不失控 | Agent 提议分支；服务端限制总预算、权限、重试与停止条件 | 换会话重置预算，或追加日志触发自己重跑，判失败 |
| 人工改动与科学判断得到保护 | 基础修订、候选、采用和授权分开；服务端核对基线 | 旧候选覆盖新手改，或接受文字顺带启动计算，判失败 |
| 组件复用，不拼接多套产品 | 外部能力经适配器进入一个项目；不复制它们整套账号、数据库与调度系统 | 用户须在多个应用间搬文件、对齐状态，判失败 |

## 1.4 实施依据与当前边界

项目交付的工程资料描述了 Python 3.12、SQLite/内容寻址存储、浏览器原生模块、对象修订与 expected_revision 检查。2026-10-06 的诊断证明：同一稿件的两个 LaTeX 出口曾采用不同生成逻辑，真实编译受缺少环境阻断；它也记录了部分编辑、批注和重开的有效实现。[I2][I3]

本书据此推荐：**验证后保留对象身份、历史、并发检查、权限和可复用领域逻辑；重建 React 工作桌并按编辑器逐项替换旧前端。** 这是前端重建和领域机制补齐，不以“局部接入”掩盖工程量；不默认重写全部后端。 “只用标准库、没有 npm 依赖”不作为交付目标。资料是带日期的现场快照，不是对当前生产仓库的实时审计；W0 必须确认现场对应关系，不能凭文档宣告旧模块全部可复用。

## 1.5 规范用语与共同术语

**必须**表示产品承诺或安全底线；**应当**表示默认实现，等效例外需由非实现的验收维护者记录依据，涉及范围、体验或权限变化由用户批准；**可以**表示可选。未标词、但规定产品功能、数据责任、权限或通过条件的肯定句按“必须”理解；明确标为例子、外部资料事实、实施候选或带“约”的视觉建议，不自动转成刚性门槛。表格的最低支持和验收条件均为必须。缺少自动测试不免除承诺，需标记未覆盖并在该关口前补齐。

| 术语 | 在本产品中的确切含义 |
|---|---|
| 数据批次 Batch | 一次采集或接收的源数据及其可核实身份；原始内容不原地改写 |
| 数据范围快照 DatasetSnapshot | 本次分析实际采用的批次、样本、标注及排除规则的固定集合 |
| 方法与配方 Recipe | 脚本、输入输出合同、参数和生成关系；不等于实际执行过 |
| 运行 Run | 基于固定计划的一次执行，包括真实输入、输出、失败与环境 |
| 科学图定义 FigureDefinition | 图回答的问题、结果引用、数据映射和基础子图构成 |
| 用途图 FigureVariant | 同一科学图用于论文、PPT、海报时的独立布局、语言和视觉覆盖 |
| 当前成熟成果 | ProjectHead 固定引用的可持续阅读成果集合；默认在用户采用完整关联修改时同步前移，可选择只保存工作稿；无须每次再点一次“设为成熟” |
| 反馈草稿 / 轮次 | 可自行整理的意见 / 提交时冻结的意见内容和上下文集合 |
| 候选 / 采用 / 授权 | 拟议变化 / 当前工作稿接纳变化 / 允许执行某项工作；彼此独立 |
| 托管约定 Delegation | 项目目标、允许动作、预算、需决策边界、回报点与停止条件 |
| 原子断言 | 具有明确输入、判断方法及可观察真假结果的单项验收条件 |
| 基线核对 CAS | 提交时比较读入修订与当前修订；不一致就定位冲突，不强写 latest |

## 1.6 全局不变量

这些规则由命令层、执行器和回归测试落实。开发任务只需列出触及的编号与检查结果；不要求每次复制整张清单，也不让研究用户填写。

| 编号 | 必须保持的性质 |
|---|---|
| INV01 | 对象身份稳定；名称、图号、目录展示与视口切换不产生重复真源。 |
| INV02 | 按 3.7 的逐类真源表只有一个权威端；文件优先与 Store 优先各有确定的提交、恢复与冲突规则。 |
| INV03 | 数据范围、代码、参数、环境与运行输入冻结；新数据不混入已启动任务。 |
| INV04 | 连接有类型与实际语义；前端、对话和脚本走同一命令及生成定义。 |
| INV05 | 来源无法核实时不假装完整；纯路径、截图和自报成功不能代替实际数据或产物。 |
| INV06 | 视口状态不改变内容，不进入科学缓存键；用途样式只影响对应渲染。 |
| INV07 | 候选、采用、授权、意见解决、科学判断分开；已知错误结果不能无提示交付。 |
| INV08 | 写入检查基线；幂等键不重复建任务，同键不同内容返回冲突。 |
| INV09 | 失败不发布半成品；采用的依赖组一致；历史交付不被静默改写。 |
| INV10 | 排除、回收和授权销毁分开；销毁优先于历史可恢复性，清除受控副本并留下不含被销毁内容的墓碑，禁止备份恢复时复活已销毁数据。 |
| INV11 | 父任务统一预算与权限；记笔记和自发回应不触发自我循环或扩大托管授权。 |
| INV12 | 验收不以改标准取得通过；独立重放、人工判断与机器检查各自注明范围。 |

## 1.7 Blender 是整合标杆，组件只是可替换的零件

产品借鉴 Blender 的对象式工作、平铺区域、可替换编辑器、素材引用与非破坏性生成，不照搬它的所有按钮、术语或快捷键。[R30] 功能模块采用成熟组件，组件的默认外观和账户系统不能成为产品布局。

| 统一语法 | 用户感受到什么 | 必须落实的约束 |
|---|---|---|
| 先选对象，再出现工具 | 从论文选中图，从目录打开笔记，相关工具自然出现 | 选择、固定、比较分别表达；对话上下文可锁定，不随全局选择悄悄变化 |
| 区域承载编辑器，不拥有内容 | 笔记可以在右侧、主区域或分屏中阅读 | 关闭区域仅关闭视图；同一文件的多个视图共享内容与冲突状态 |
| 有限默认，按需展开 | 左侧成熟成果，右侧当前笔记；树、属性、对话按需取出 | 首屏不同时展开文件树、素材卡片、任务表、节点图和聊天；可一键恢复默认布局 |
| 引用与独立副本有区别 | 一项结果可服务论文、PPT及其他项目 | 共享引用、独立副本、本地覆盖、解除引用是明确命令；引用更新先提示，采用稿与交付快照不被静默替换 |
| 生成定义可改，实际证据不抹去 | 改参数能重算，旧结果仍可解释来由 | 输入、实际输出和运行记录保存；视图缓存可丢弃，科学证据不能当缓存清理 |
| 同一种工作使用同一种动作 | 查找、选择、删除、返回、保存的含义可预期 | 统一命令和键盘分派；原生文件外部修改经同步入口登记，不禁止用户使用其他 Markdown 编辑器 |

“轻量”指默认负担低、按需加载、运行与界面解耦，不指减少已承诺功能或把可靠性转交给模型。“优雅”通过统一间距、图标、焦点、选择、反馈和错误恢复实现，不靠给所有组件涂同一种颜色。所有操作可查看范围与后果；局部编辑可撤销，计算可取消或恢复，但已发生的模型外发、现实实验和发布不能伪装成可完全撤销。

附件建议的逐条取舍及组件源码入口见《笔记与工作桌设计依据》。它是设计来源说明，不是另一个规范主本。完整产品范围不因某一旗舰项目暂未使用而删除，也不预先承诺未经资源与迁移测试支撑的长期维护年限。

# 二、产品怎样回应真实工作场景

## 2.1 工作桌：成果与笔记并置，编辑器按对象切换

**默认现场。** 打开项目，左侧约三分之二显示明确采用的成熟成果，右侧显示该项目上次工作的笔记及其位置。比例可拖动调整并按项目保存。右侧有“笔记／搭档”的短标签，切换不丢笔记或对话；需要同时使用时，把对话拆出或临时打开底部区域。纯阅读可以最大化成果，Esc 返回原布局。数据探索阶段允许将实际勘察报告设为当前成果，不用空论文占据全部空间。

![成果与项目笔记的默认工作桌](assets/01_成果工作桌.png)

*图 1｜界面规格图：默认只保留成果、笔记和少量上下文工具。它不证明成熟组件已完成集成，也不作为可操作应用交付。*

**区域。** 每个区域有一致的编辑器选择器、对象标题、面包屑与必要状态。拖动区域边界改变空间，拖动标签可停靠或分屏；关闭标签不删除对象。每个区域都可承载已注册且实际支持的编辑器；无适配器时提供诚实的源文件或只读视图。固定某份成果后，其他区域的选择不抢走它。临时预览与固定打开分开，返回恢复对象、选区、位置和比例。

**导航。** 项目素材树采用受控的紧凑层级树，平时收起；笔记在当前区域内打开自己的导航抽屉，不另开整套应用。文件树、对象树、生成图是不同视图：文件移动只改位置，节点连接改生成关系，从文章移除图只解除引用。选中的实际对象与来源信息在这些视图中联动，必要时显示多个使用处而非猜一个位置。

**公共操作。** 全部素材视口提供平移、缩放、适配内容、适配选区、100% 和返回。长文、代码与表格使用滚动和显示倍率，图形与页面使用二维视口；不改变正文、字形设定、数据坐标或实际纸面尺寸。文本输入时空格用于输入，输入法组合未完成时不提交命令。每个分屏独立保存视图状态，内容撤销与视图历史分开。

**视觉规范。** 中性深灰控制外壳、浅色成果纸面、低干扰笔记底色；同一套图标、间距和状态颜色。选择强调只用于当前对象和焦点；等待、冲突、失败使用文字与图形共同表达。常用工具用图标和悬停/聚焦说明，“新建批注”“处理本轮”等关键动作保留短标签。桌面默认控件高度约 28–32 CSS px，密度可调；触摸模式放大命中区，不能把桌面小图标原样缩到手机。工具栏溢出进入固定更多菜单，不缩成无法点击的小字。

**可发现性。** 通过可见的“快速打开”和“搜索项目”按钮进入；桌面浏览器默认 Ctrl/Cmd+K 快速打开，Ctrl/Cmd+Shift+F 搜索项目，编辑器聚焦时 Ctrl/Cmd+F 查当前文档。Ctrl/Cmd+P 保留浏览器打印，不作为必需应用命令；冲突或宿主无法拦截时保留等价可达按钮。快捷键可调整，输入焦点优先，不强搬 Blender 的 F3/F9。命令搜索与编辑器工具栏调用同一命令，专业详情可查看参数和影响。长任务在后台运行，局部状态和恢复动作留在对应对象旁；不不断弹出模态确认框。

**验收抓手。** T21、T28 检查真实组件的停靠、焦点、键盘、输入法、撤销、面板恢复与不同屏幕。组件自带演示页不能替代统一工作桌中的同一组测试。

## 2.2 有数据、无明确方向：先勘察，再试探，再收束（N01）

**起点。** 用户加入数据及说明，提出：“先看看能研究什么，优先已有分析，不做大训练。”系统建立只读输入引用和论文模板，当前打开数据勘察报告，而不生成虚构正文。

**Agent 的第一项工作。** 实际读数据和说明，核查身份、字段、单位、样本/条件覆盖、重复和缺失；读取已有脚本和结果但不自动执行未知脚本。把已核实事实、推断与缺失分开。外链打不开就记录不可访问，不写成已读。

**返回可决定的结果。** 数据勘察报告含代表性质量图、适合或不适合开展的比较，以及多个候选问题。每个问题都有数据依据、相关文献、最小先导、投入上限与停止条件。默认突出一项推荐，其他方向仍保留在同一笔记中，不把低认知负荷误作只允许一个方向。

**形成有边界的一轮工作。** 用户可选若干方向并限定预算，也可请搭档推荐。Agent 建立实际分析节点与先导任务；常规方法实现自主完成，重大科学或资源分叉再解释并求决定。先导返回图、结果数据、检查与阴性发现，双方据此继续、合并、暂停或转向。

**保存与恢复。** 每个方向关联同一组源素材，保存尝试与判断，不复制整个项目。探索中形成的假设标记其形成依据；后续验证使用明确划分，不能把同一批反复筛选后的结果自动当成独立验证。话题摘要写入 Markdown 笔记，任务回报按任务记录。

**验收抓手。** T01：没有题目也能开始；T14：真实 Agent 在陌生但有说明的数据副本上完成调查和受限先导，给出可追证据的建议；只有泛泛选题建议或预置回复不通过。

## 2.3 加数据、改参数：一次提交研究变更（N01、N02、N03）

数据是一类需要持续管理的源素材，而不是导入一次就结束的附件。产品必须同时管理**源批次、分析采用范围和整个下游计算流**；三个层次各自有稳定身份与历史。

**添加与删减。** 新采集、新条件、标注更正或替代处理先作为独立批次/修订接管，核查身份、单位、覆盖与重复。用户可排除某次记录、样本或条件并说明原因；排除作用于一个分析范围快照，不物理删除源数据。恢复排除项形成新快照。实际销毁源数据是单独授权动作，先列出受影响的运行和交付依赖；法律、伦理或授权要求必须销毁时照要求处理，并诚实标记不可再复现范围，不能以历史保护为由拒绝。

**数据范围必须可核对。** 快照记录批次引用、实际纳入成员清单及摘要、排除原因、标注/身份映射与选择规则。仅保存一段动态筛选表达式不够，后续添加数据不能偷偷改变它的结果。大型数据引用可验证的外部不可变版本；无法固定外部内容时降低保证并禁用相应可信缓存。界面优先显示“新增了哪些、移除了哪些、当前结果采用什么”，底层 ID、哈希按需展开。

**计算流的变更计划。** 用户一次提出“把新增记录纳入，排除质量不足的那次，重新检查这张主图”。`build.plan` 根据固定成员、参数和已登记依赖确定复用、重算、重绘与重新排版；输出唯一 plan_hash 和清单。Agent 引用这份计划解释研究影响，不另生成一份可覆盖它的重做决定。已登记 Claim/Evidence 关系触发对应表述待复核；未登记段落可由 Agent 扫描提出候选关联，须标为推断、核查后登记，不冒充完整依赖覆盖。重复的数据接管、预处理和共享结果不在每份成果下重算。依赖全体数据拟合的步骤必须重算全体适用范围，不未经验证只算新增行再拼接。

运行中的计划固定输入。第二批数据尚未完成时又加入第三批，可以先合并尚未启动的变更计划；已经启动的运行继续原快照，取消需真实终止。调度按节点重算身份去重，避免论文和 PPT 各自要求同一结果而重复消耗计算。用户看到一份研究影响摘要，而不是数百个路径。

**参数纠错。** 从主图点开实际运行中的脚本与配置，核查产生当前结果的参数，而不只读最新配置文件。确认错误后标记相关结果为已知错误，提出修复和必要检查。代码修改先成为新方法修订，显示 I/O 合同与受影响范围，再运行；导入或打开脚本不自动执行。

**回报与采用。** 新结果、图、图注、方法和论断按关联组比较；能匹配的视觉覆盖重放，新增/失去的元素列明。科学结论变化必须解释，不只替换数字。“旧范围仍有效”“结果已知有错”“结果已完成但未采用”分开。历史稿固定其原来依据，不被更名覆盖；不同用途稿可保留不同范围，但每份稿内部约定的依赖一致。

**连续验收情境。** 批次 A 建结果 → 加 B → 排除 A 中一项 → 加 C → 恢复被排项 → 更正标注或参数。每次均核查成员差异、实际重算集合、保留分支、图/文采用及旧稿，不只做一次追加数据的演示。T05/T22 检查全周期，T06 身份错位，T07 中断，T11 关联采用。

## 2.4 改主图：直接操作外观，搭档处理复杂返工（N04）

| 用户动作 | 软件直接完成 | Agent 何时介入 |
|---|---|---|
| 选中子图，从此主图移除 | 解除组成引用、保留源素材，重排并可撤销 | 被移除子图支撑了正文论断时，检查图注与正文，提出改写或移到补充材料的建议 |
| 多选轴区，统一高度/间距 | 对齐真实轴区，不把图注外框当轴区；锁定对象不动 | 全图层次不清但用户没确定布局时，提出符合约束的候选 |
| 同组轴线、字号、图例位置调整 | 预览命中成员和混合值；只改选中语义组，保存覆盖定义 | 不明确元素对应、源对象不支持、或需要复杂重排时 |
| 改筛选、尺度、统计或归一化 | 明确影响科学解释；不伪装成纯样式 | 核对方法、必要重算、检查结论并返回证据 |

临时隐藏只影响查看；从成果移除影响实际导出；删除源素材是单独动作。主图和子图身份不取决于 A/B 或 Figure 1；图号由位置计算。删除或重排后，系统更新有效引用，对失去依据的文字给出具体位置，不能把所有字母机械替换。

布局、源绘图脚本、结果引用和视觉覆盖分别保存。GUI 和 Agent 写回同一覆盖定义；图数据重绘时重放。必须覆盖第 3.9 节支持矩阵中的曲线、散点、轴线、刻度、文字、图例、色条及主/嵌入轴；矩阵不是按已实现结果反向填写的清单；导入静态 PNG 只给整图布局和批注，不假装还原 Matplotlib 结构。

**验收抓手。** T08 同一图在热态编辑、冷启动重绘、保存重开与导出后匹配；同时对比源数值不变。只证明 SVG 上有线条可拖动不算通过。

### 同一结果用于论文、PPT 和海报

共用的是结果源数据、方法、科学图定义和实际生成依据；不是让所有成果强用同一个最终 PNG。主图可拥有论文、PPT、海报等**用途图**，各自保存布局、尺寸、文字语言、元素大小、配色和图例覆盖，并有独立身份与主入口。成果引用具体用途图及其采用修订。用户在 PPT 中放大字体只改变 PPT 用途图，论文不变；复制科研结果以“隔离样式”不成立。

新建用途图默认继承明确的科学图修订，只保存差异，不建无限派生链。通用科学修正产生候选，所有使用处可定位并分别接纳；已提交快照不静默跟进。子图可以在不同用途组合中省略或重排，但源素材保留，并核查图注和论证不因省略而失真。

**展示差异与分析差异有边界。** 换字体、尺寸、布局和允许的可视映射属于用途；改变样本、统计量、归一化或科学筛选必须建立对应分析/绘图定义修订，不能藏入样式文件。共享结果发生变化后，各用途图按自己的覆盖重绘；匹配失败明确定位，不能丢失人工编辑再称更新完成。T24 用同一结果生成论文与 PPT 两份不同布局，验证单独改图、上游变化和历史保护。

## 2.5 审阅与科研对话：整轮处理，按需采用（N05、N06）

工具栏具有阅读/审查/编辑状态、新建批注、修订开关、标记显示、上一项/下一项、接受/拒绝及“交给搭档处理本轮”。审查模式的增删替换保留作者与建议，不立即改变采用稿。正常阅读隐藏已处理标记，历史仍可恢复。

**用户先整理意见，再决定是否委托。** 自己的批注可编辑、删除和撤销删除；自己的修订可接受、撤销、保留待审或排除出本轮。删除未提交批注后它不出现在正文标记、待发列表或实际发送内容，采用稿不变。拒绝自己的建议替换恢复建议前的采用内容，而不是再生成一条给 Agent 的意见。批注与其派生文字候选有关联时，操作明确是否一并撤销候选，不能留下找不到来源的待采用项。

删除是用户可直接做的内容整理，不需要模型同意。对于已提交或运行中的意见，界面提供“撤回并从当前工作中隐藏”：服务端保留已提交快照作运行依据，同时发出撤回控制；未开始部分停止处理，迟到候选不能自动应用。已经发送给外部模型的内容不能宣称从对方记忆中撤回；已采用修改也不会因删批注自动回滚，需要单独撤销。删除、解决、隐藏和撤回分别标明，恢复记录按必要权限管理，不以审计之名把每条误写意见永久占据界面。

![审阅工具栏的界面参照](assets/08_审阅工具栏细节.png)

*图 2｜审阅是成果本身的工具，不要求用户先进入聊天才能批注。*

意见的编辑、删除、恢复、撤回由服务端校验作者与主体：用户可整理自己的意见；Agent 只能回复用户意见或在提交前整理自己创建的草稿，不能删改、撤回用户反馈或代其解决。科学异议不赋予控制权限。

用户连续审阅多个页面和主图后，一次提交一组意见。服务端固定本轮 feedback_ids、每项意见的内容修订、相关对象修订与用户边界；不能用前端当前筛选列表代替“全部”。处理中新增意见进入下一轮或明确追加，不悄悄改变正在处理的范围。

Agent 先读整轮，归并重复依据、识别矛盾，再分组调查与执行。返回一份总判断和每条意见的 disposition：同意、部分同意、有据异议或尚不能判断；每项同时包含证据引用、候选修改、阻塞和下一步。科学上不同意不是执行失败，未处理也不能伪装成不同意。“逐项有回复”仅证明覆盖，不证明整轮完成：证据与工具均已具备的确定性意见必须实际处理并引用证据；材料不足的事项可以尚不能判断，但保持未完成。不设迫使模型下结论的固定未知比例。

采用所选组时发送明确的 change_ids 与基线修订。服务器检查对象基线；旧候选遇新手改时保留候选，定位冲突。无关组仍可采用；相互依赖的一组不得一半生效。批注解决、修改采用、科学确认和计算授权是不同状态。

右侧对话显示当前对象/选区的上下文条，可固定、移除或引用笔记片段。截图是带时间和范围的可预览附件，限获准应用区域，用来核查指代；不代替读结果数据，也不自动截取桌面其他窗口。模型没有连接时明确不可用，已有内容仍可编辑。

**验收抓手。** T23 验证草稿删除/恢复、人工修订保留/撤销、已提交撤回；T09 仅对提交时明确保留的意见一次处理、不漏不多；T10 旧候选不覆盖新手改；T11 批量采用范围与状态正确；T14 必须有真实模型的来源核查和至少一个有依据的异议场景。

## 2.6 每个项目都有独立的 Markdown 笔记系统（N06）

**文件是笔记本身。** 每个项目必须有专门的 `notes/` 文件夹。新建笔记立即创建 UTF-8 `.md` 文件，保存直接更新该文件；不是先存数据库、最后“导出 Markdown”。复制 `notes/` 就能用普通文本编辑器阅读正文和相对路径附件。搜索索引、缩略图、视图状态和修订缓存可以在 `.partner/` 中重建，不是第二份可独立编辑的正文。

**组织。** 默认有入口说明、随手记、按日期组织的实验日志、按问题组织的主题笔记和附件目录；用户可增删和移动子目录，已有笔记不强制迁移到单一分类。日志以任务或讨论条目为单位，不按点击或一次模型调用生成文件。任务计划、问题、判断和实际工作回报分开表述。主题和日期导航是同一组文件的不同索引，不复制两份笔记。新项目只创建必要入口，其他目录按首次使用创建。

**导航必须完整。** 笔记区域的导航抽屉包括实际文件树、当前文档标题大纲、最近打开、固定收藏、日期入口、标签和反向引用；后退/前进恢复原段落。用户从“最新工作简报”可定位到具体文件和条目，从条目又可打开主图、任务或对应结果。全图谱是可选专业视图，找笔记不需要在节点海中寻找。

![项目笔记的目录、大纲与检索](assets/12_项目笔记检索.png)

*图 4｜界面规格图：检索结果保留文件名、路径、匹配片段和定位入口；正文仍是 notes 中的 Markdown，不是搜索卡片保存的副本。*

**检索。** 默认搜索当前项目 `notes/` 中的文件名、标题、正文和标签，可按目录、日期、笔记类型或关联任务/素材过滤。查询结果显示实际片段与位置，打开即定位并高亮；两字中文、中文子串、数字、英文缩写和公式文本都要验证，不能只支持英文整词。跨项目搜索必须显式扩展范围，并检查每个项目权限；向 Agent 引用命中片段时显示将发送的内容，不自动外发整本笔记。检索无结果、尚未索引、文件不可读和索引异常是不同状态。

**编辑。** 同一编辑器提供 Markdown 编辑和阅读预览，可拆分并同步到相关位置。标题、列表、表格、代码、数学与图片使用明确的语法支持矩阵；格式工具写入真实 Markdown。未知扩展语法原样保留并提示不支持，不经富文本往返静默丢失。局部撤销、文内搜索、自动保存状态、只读和冲突提示属于基本能力。阅读视口保留公共导航，文本编辑不被平移手势抢焦点。

**外部编辑与安全保存。** Agent、界面和普通编辑器看到的是同一文件。应用写入核对基础内容摘要，采用安全写入和失败恢复；检测到外部修改且本地没有未保存内容时可重新载入，存在并发手改时展示差异并保留双方，不整篇覆盖。重命名保持笔记身份并检查相对链接；外部重命名无法唯一识别时提示修复，不用相同标题强行认定身份。删除进入可恢复回收区，默认搜索不包含回收项；移除面板不是删除文件。

**日常协作。** 用户在成果旁随手记问题；选中片段后可“与搭档讨论”或“拟为任务”。前者只加入对话上下文，后者生成待确认或按既有授权推进的任务，保存笔记本身不触发执行。讨论收束后形成带时间的摘要、依据、分歧及下一步；任务完成或形成重要阶段结果后追加一条任务级简报。用户的自由笔记不要求每句话都填元信息，不因未结构化而拒绝保存。

**引用与接续。** 任务引用具体笔记、条目及当时的内容摘要，保留可读摘录与来源。完成任务追加简报不会触发原任务重跑。引用过的内容后来删改时，当前导航尊重文件内容，历史运行引用仍可检查当时快照；科学状态和新授权不能由笔记摘要自动改变。最近打开、收藏和全文索引按项目隔离，同名文件不串项目。

**后台工作。** 任务在服务端继续；浏览器断开不取消。暂停采用停止派发并等待安全检查点的语义；正在运行的不可暂停步骤明确显示“暂停中，当前步骤仍运行”。取消要求终止进程树或核实远端取消回执；只有提供者声明且实测支持时才暂停进程本身。父任务统一维护预算和预留。重复请求不重复启动工作；状态不确定先核对既有任务，不盲目重发有副作用的操作。断线编辑只记作本地未同步，未收到项目文件写入确认不得显示“已保存到项目”。

**验收抓手。** T12、T27 验证创建即落盘、无需导出的外部读写、导航检索、双项目隔离、短中文查询、索引重建、冲突、移动链接与引用快照；T13 验证真实后台恢复。具体文件、组件及服务边界见 3.8 与 A.6。

### 项目托管与再次进入

用户可以授权搭档托管整个项目，而不必逐项派发普通工作。托管约定记录目标、当前任务清单、允许的数据/代码/成果操作、费用与算力上限、需用户决定的事项、回报点和停止条件。进入托管不等于新增实验、任意数据删除、无限模型调用或对外发布授权。默认仅自动生成候选；用户可一次性授权特定项目/对象/动作的低风险自动采用，如任务简报和纯视觉覆盖。该授权有期限、预算及检查条件，不能由 Agent 自我扩权；科学论断、数据范围、用户反馈与发布权不在默认自动采用集合。未配置真实后台与提供者时只能保存计划，不宣称已经持续工作。

Agent 在约定内调用同一工作台/工坊领域工具：检查成熟成果与任务状态，调查证据缺口，细化任务，安排有用并行，执行、审查、形成候选并写任务简报。结构化接口执行确定工作；需要视觉确认时可查看获准截图。用户进入不强制打断全部后台，但人工编辑和新意见必须得到基线与冲突保护；“暂停托管”作用于真实排队/运行状态。

重新进入项目时，右侧笔记提供一段**接续简报**：离开后完成什么、哪些失败或仍在运行、成熟成果是否改变、有哪些候选、下一步首选和需要用户决定的事项。简报基于实际笔记条目、任务和产物，不靠摘要猜测成功，不把最近修改文件当成熟稿。

任务优先建议围绕“当前证据再前进一步最需要什么”：先保护可靠性与解除关键依赖，再比较预期认识收益、成本和可执行性。Agent 给出一个首选行动及理由，必要时展示少量替代；用户可调整顺序，也可共同讨论成果的最近发展区。不能只用“容易做”排序，也不把固定打分当科学判断。T25 核对托管边界、真实进展、用户中途介入与接续简报。

## 2.7 转投、换语言、改篇幅：不复制研究工程（N07）

同一项目分别管理科学依据、表达稿与投稿配置。转投时保留 A 的提交快照，创建 B 的表达/配置组合；共享数据与主图源，只对 B 需要的布局建立用途覆盖。Agent 从当时有效的官方要求提取稿件类型、篇幅、图表和引用规范，保存来源及不确定处。

纯模板修改只重新排版；图尺寸变化可能重绘；减少主图、删结果或重组论证是实质修订。中文到英文生成关联表达稿，统一术语、图中文字和图注，核查数值、单位、限定语和论断强度；中文后续变化只标出相关英文待复核，不覆盖人工英文润色。

压缩篇幅先明确计数口径，再围绕论证提出删并或补充材料安排；不靠缩字号达成字数目标，不删必要方法和限制以制造更强结论。正式文件来自当前采用内容和目标模板；预览与下载调用同一生成入口。

**验收抓手。** T15 同一科学结果适配两个模板，中文/英文及两种篇幅分别核对；引用、主图、公式和保存的旧提交稿均不受无关破坏。

## 2.8 其他成果、工坊与项目完成（N08）

报告交付问题—方法—结果—限制的可读正文及依据；正式研讨笔记保留论证与分歧。概念图有可编辑的节点、文字与关系。海报在实际尺寸画布编辑，PPT 有可重排页面及逐页讲稿。它们共享科研素材，但不机械粘贴论文，也不把 PDF 预览当成可编辑源。

五类工坊任务分别是刺激准备、图像/标注清洗、神经数据预处理、可视化工具开发、实验软件开发。每类需要自己的输入校验、任务模板和结果检查；公共执行器不代替领域验收。实验硬件与人类操作没有真实条件时标为受阻，不模拟成完成。

项目结束要留下可阅读成果、可编辑材料、关键生成定义、文献、运行与恢复说明，以及贡献、限制、未决问题和停止理由。投稿、发表、实验结束与项目内部完成分别记录。独立机器能够按声明依赖接手；原主机上的隐藏状态不算交付。

**验收抓手。** T16 按五种工坊分别检查，T18 检查可编辑成果，T29–T32 检查研究知识、成长、权限与运行机制；任一通用脚本成功不代签这些能力。

## 2.9 以主图审查科学工作：图、结果与代码直接耦合（N02、N03、N08）

主图是审查入口。用户选中主图时，工作桌在可收起的来源托盘中显示**产生当前所见图的实际链路**：数据范围快照 → 预处理/分析脚本及参数 → 结果源数据 → 子图绘制 → 主图布局/用途图 → 当前成果。图中位置与属性仍可操作，来源视图不另开脱节的系统。双击可进入编辑；目录、节点和画布对同一对象联动。

每个计算环节可以是一份有明确输入输出的 Python 或其他受支持代码文件，也可以是可展开的节点组。节点首先给出这一步解决什么、输入/输出与运行状态；选择后直接读脚本、配置、环境、实际运行日志和数值预览。不能只有描述性说明、图片或指向“最新版脚本”的链接；必须定位生成这份结果的代码修订。

视图明确切换“当前采用结果的运行图”和“待执行配方图”。前者忠实显示历史实际输入，后者用于计划修改；改变待执行参数不能让历史图显示成已经按新参数运行。中间结果缺失、手工处理未登记、外部代码依赖不明或来源只到部分环节时，在断点显示未知，禁止自动补画一条完整溯源链。

用户可在任一节点批注“这个筛选是否合理”，与稿件其他意见一起成轮；Agent 读取对应数据和代码后回应、提出修复或有据异议。仅想检查不触发计算；明确修改参数后生成变更计划，决定复用、重做及图文影响。T26 检查当前主图到实际脚本/参数/结果的连续定位，以及缺依赖时诚实停止。

## 2.10 研究知识、可复用能力与有证据的成长（N06、N08）

研究图谱组织“问题—假设—证据—限制—未决事项”，与计算依赖图分开；同一素材可参与二者。Agent 提出新关系时记录实际来源和作者，既有用户判断不被自动改写。文献工具需实际检索、解析来源、记录读到全文还是摘要、保存可定位片段及引用条目；网页搜索标题不是全文阅读证据。

自然语言委托先路由到适用成果类型和领域约定；缺少输入时做调查而非预填成功。刺激准备、数据预处理等插件必须声明输入输出、权限、运行环境和检查。扩展可安装、停用和卸载；停用不删除已有结果，历史素材显示其提供者是否可用，卸载后权限令牌失效。

成长候选绑定一个真实失败或外部方法，使用相同输入、预算及独立判据与基线比较；无收益、超预算或造成退步不采用。用户可查看来源、实际比较和回退入口，不必维护评测台账。T29 检验文献/图谱/路由，T30 检验成长与扩展；它们不能由通用“体验通过”代签。

# 三、实现方案：复用成熟组件，补齐科研领域机制

## 3.1 采用一条技术路线，不把整套开源产品堆在一起

**推荐组合：保留 Python 对象服务和存储；用 React/TypeScript 构建对象工作桌；受管稿件使用 ProseMirror；真实排版由隔离 TeX 工作者完成；科学计算由 Snakemake 适配器执行；图形优先接入 Tavotto 能力；Agent 通过现有原生 Harness 适配层调用受控工具。** 下表定义职责，不表示已安装或兼容测试通过。具体依赖在 W0 锁定，不使用浮动 latest。

| 部件 | 选用/复用方案 | Research Partner 自己负责什么 |
|---|---|---|
| 可拆分工作桌 | Dockview 开源包；React Arborist 素材树 | 对象选择、上下文、回到原位、公共视口、权限和一套视觉规范 |
| 节点编辑 | React Flow | 有类型的生成定义、合法连线、计划与执行；它不负责科研调度 |
| 稿件审阅 | ProseMirror + Manuscripts track-changes 插件 | 科研 schema、批注锚点、整轮反馈、基线冲突、采用与真实排版 |
| 原生笔记系统 | CodeMirror 6＋Markdown 语言/搜索扩展；markdown-it＋DOMPurify；复用 Arborist/Dockview | 每项目 notes 文件服务、全文索引、链接/大纲、冲突、项目权限与引用快照；详见 3.8 |

| 海报、结构图、幻灯片 | Konva 场景编辑；PptxGenJS 导出 | 可编辑场景结构、科学素材引用、版面规范、实际格式适配 |

## 3.2 写入责任：四种界面，只改变一份工程

组件关系如下；箭头表示调用边界，不是独立需要用户维护的系统。

```text
工作桌：稿件 / 图 / 笔记 / 目录 / 节点       科研搭档对话
                 │                           │
                 └──── 同一组领域命令 ────────┘
                              │
        对象服务：身份、修订、权限、审阅、采用、任务
                              │
          生成服务：类型校验、输入快照、计划、产物核验
                 │              │              │
           计算适配器       图形适配器       排版适配器
            Snakemake         Tavotto        TeX/Pandoc
                 └──────── 实际产物与运行证据 ────┘
                              │
              修订存储 + 文件工作副本 + 可恢复交付
```

应用前端不能直接修改数据库或绕过命令写成果；外部编辑器修改原生 Markdown 后，由文件同步入口检查基线并登记，而不是强制禁止外部编辑。Agent 不能用任意 shell 覆盖采用稿、改验收状态或编辑最终 PDF。领域命令验证权限、对象基线与幂等请求，然后创建新修订。HTTP 原入口可以保留，新增字段经适配，不为换前端而强制重写服务器。

产品任务服务管理委托、预算和采用；Snakemake 仅调度一次固定计划中的机械计算。Agent 可以在下一轮建立新图，不在执行中的 DAG 里随意改变输入。浏览器只订阅工作状态，不拥有后台执行的生命期。

## 3.3 文稿真源：选择可实施的双类型，而不是两个同时可写的主本

**受管稿件**的权威内容采用结构化 document.json。ProseMirror 在稳定 block_id 的标题、段落、公式、引用、图位、列表与表格上工作；Store 保存修订，main/document.json 是可移交的工作副本。真实 LaTeX 是该内容经已注册序列化器生成的派生物，main/render 中的 PDF 与 TeX 不作为第二套可随意写入的真源。

理由是修订、批注、整轮回应和素材引用需要结构化锚点。把正文一边存为块、一边允许独立修改 main.tex，会重新产生“编辑、预览和导出内容不同”的问题。受管稿件仍提供原位编辑与排版位置定位，不要求用户日常阅读 JSON。

**原生 LaTeX 稿件**以 main.tex 和其依赖为真源，使用 CodeMirror 和真实 PDF/SyncTeX 位置定位；源码修订、批注与补丁可追踪。任意宏包和外部 PDF 不保证无损变成结构化富文本。导入时保留源文件与支持报告，无法映射的部分仍可原生编辑；不能因为自己生成的受管稿件可审阅，就宣称任意 PDF 可反向编辑。

两类由 authoring_mode 明确标记，一次只有一个权威表示；转换要产生新修订并校验公式、引用、图位和文本。用户不是在两个不同论文产品间搬运，而是在同一稿件上使用实际可用的编辑能力。受管模式在 W1-b 通过最低语义矩阵，原生模式及受限转换在 W4 通过各自矩阵。它们是同一对象工作桌的两类编辑适配，不宣称 W1 已支持原生模式的全套审阅。转换生成新稿件对象并保留来源，不覆盖原源；转换不支持的宏/环境原样保留在原生模式。

预览和正式下载调用同一个 render(manuscript_ref, template_ref, projection)；projection 明确为 adopted 或 review。默认正式输出只包含已采用内容，待接受修改、批注和工坊笔记不漏入。页面点击映射到 block_id 或图位；无法确定时显示位置列表，不伪造精准选区。

## 3.4 素材与生成图：存什么，执行什么

**DataBatch** 记录源批次，**DatasetSnapshot** 记录固定采用集合，**FigureVariant** 记录成果用途，**Delegation** 记录项目托管边界；**Asset** 是有身份的工作对象；**Revision** 是该对象某次明确内容；**Recipe** 是如何加工和组合的定义；**Run** 是一次实际执行；**ChangeSet** 是待采用的修改；**Release** 是固定的交付集合。图上的位置另存为视图状态，不进入科学计算缓存键。

| 关系/节点 | 输入与输出 | 变化怎样传播 |
|---|---|---|
| 数据源 / 范围 DataSource / Dataset | 批次及固定成员、标注/排除映射 → DatasetSnapshotRef | 批次、纳入/排除、更正分别登记；只改变选择了新范围的分支 |
| 分析 Analysis | DataRef + 配置 + 脚本/环境 → ResultRef | 相关输入或方法改变则重算；未知外部依赖禁用可信缓存 |
| 子图 Plot | ResultRef + 字段映射 + 图形定义 → PanelRef | 数据变则重绘；样式变只重绘，不做统计 |
| 主图 Figure / 用途图 Variant | 科学图定义 + 结果引用 + 子图 / 用途覆盖 → FigureRef | 共享结果，论文/PPT分别生成；源变动可追及所有用途，采用不静默传播 |
| 文章 Manuscript | 表达稿 + figure_slots + 文献 + template → RenderBundle | 图位和模板改变装配/排版，不自动改论断 |
| 智能工作 AgentTask | 固定上下文 + 目标 + 预算 → 调查/方案/候选 | 实际输出落盘，重建成果复用已采用输出，不重复调用模型猜一次 |
| 证据关系 Evidence | 结果/来源 + 判断 + 解释 | 依据变化标记待复核，不自动改写科学结论 |

端口检查不只比文件扩展名：必须检查 required/optional、单值/列表、schema、身份列、单位和样本范围。两个相同形状的矩阵也可能顺序相反；显式映射节点可转换，不能静默纠正或丢列。组合节点能够展开内部生成步骤，普通用户不用编辑节点即可操作相同关系。

文章增加 figures 图位时创建稳定 slot_id，图号按顺序计算；空位可以留在草稿，正式交付检查未完成图位。模板端口只接模板对象；结果不能直接塞进图位冒充主图。可反馈的研究循环体现在下一次修订/任务上；一次机械计划仍为有界依赖图，显式迭代必须有停止条件。

受管脚本调用采用显式输入清单、参数文件、输出目录和环境引用；产出后读 outputs manifest 并核验实际文件。导入的未拆解脚本可以暂存为不透明来源，但只能通过“接管并如实显示缺口”，不能通过完整主图链路验收。受管主图至少暴露每个影响科学含义的筛选、汇总/拟合与绘图边界，参数定位到脚本修订和配置键，中间结果确实存在。检验用至少两项有不同科学职责的计算及实物交接，不能用两个空节点凑数。图的运行投影从 Run 读取，不从当前 Recipe 倒推历史。

跨成果重做以节点身份和内容依据合并，共享结果只有一套来源；各用途渲染有各自配置键。数据排除策略属于分析输入，视图中隐藏一个对象不等于排除对应样本。新快照与旧快照的成员清单可做差异检查，并成为科学解释的来源。

## 3.5 执行秩序：由程序保障，不靠提示词保证

**唯一重做裁决者是产品生成服务。** `build.plan` 固定目标、输入范围、代码、配置、环境和随机性说明，按内容及执行条件产生 plan_hash、复用集合与待执行集合。Agent 解释计划而不修改结果。`build.start` 只能执行该计划；开始时核对授权、输入可读性与计划有效性，源改变须另建计划。

**Snakemake 负责计划内调度，不再二次决定产品缓存。** 产品按已验证节点键复用不可变输出；仅把待执行节点编译到本次受限 Snakefile，复用项以只读外部输入注入，不能保留可再生成它们的规则。所有待执行目标使用新的 attempt 输出路径。锁定版本后检查 dry-run 的实际 job 集合等于计划集合，再执行；复用项不得因 mtime 变化而加入。不能对全量图直接 `--forceall`，也不认为关闭一种 rerun trigger 就自动达成一致。Snakemake 官方说明 forceall 会连依赖规则一起强制执行，相关参数仅能在受限图上经合同验证使用。[R32]

适配器的完成与失败事件用于调度和诊断；跨次缓存账本由产品维护，不依赖临时 staging 内的 .snakemake 历史。任何计划外 job、缺输出或错误复用都拒绝发布。恢复时重新核对已完成节点证据，按原输入快照生成剩余计划，不无条件全跑。

**输入与环境。** 大数据初次授权接管时可流式校验一次；后续按不可变外部对象版本、分块摘要与已核验清单复用，不在每次打开项目时重扫 TB 数据。仅有 mtime/采样指纹不能标记为强身份。Environment 保存锁文件、解释器/平台、镜像 digest 或可核查安装清单、字体/模板及确定性条件；`pip freeze` 文本本身不构成可移植环境。环境保证分“同环境可重建”“经测试跨机可重建”“未知”，并进入计算身份。

**输出发布。** 每个 attempt 在隔离目录输出；退出码成功后仍核对文件、字段、成员、数值与约定科学检查，再登记不可变输出。文件/表只写一半、截断模型响应、缺子图或旧 PDF 均不是成功结果。输入、结果和证据缺口独立记录；只读预览旧结果时明确标旧。

**控制。** 请求幂等与真实远端 job_id 分开保存。暂停先停止新派发，已运行任务进入 drain 或提供者支持的检查点暂停；UI显示“暂停请求/暂停中/已暂停”的实际区别。取消需终止进程树或收到远端回执；不可确认则 unknown，不标 cancelled。恢复从已核实检查点或明确节点重启，不承诺任意程序的指令级继续；有副作用的请求超时先查原操作，不能盲重发。

run_status、freshness、adoption 与科学审阅分别存储；运行成功并不自动修改成熟稿。父任务限制贯穿所有子任务，日志与 Agent 自发回应不重新派发原任务。T04–T07、T13、T22、T26、T32 分别检查计划、复用、产物、恢复与环境。

## 3.6 接入 Agent：明确工具，不给无约束文件写权

默认保留既有 Harness 原生适配方向，锁定其实际版本与插件接口。DeepSeek Harness 官方定位为插件架构且提示开发预览兼容风险；它不替产品完成科研 schema、预算和素材管理。[R10]

科研工具集合为：project.inspect/resume_brief、delegation.configure/control、dataset.snapshot/diff、provenance.resolve、variant.create、asset.read/import、literature.search/read/register、recipe.propose、build.plan/start/status/control、figure.inspect/propose、review.respond（用户意见只读；自有未提交草稿另经作者约束）、changeset.propose、notebook.append、screenshot.capture。工具名字是本产品的适配契约，不冒称第三方同名 API。不同模型共享这些入口，密钥不进入项目内容。

Agent 工作回合固定为：读取当前目标和证据 → 调查必要材料 → 提出或细化可执行工作 → 服务端检查范围与预算 → 执行受控工具 → 验证并解释结果 → 提交候选及任务简报。已经批准的常规步骤可连续推进，不逐节点询问。调查发现假设不成立时说明证据，并提出继续、改题或停止的推荐。

整个父任务共享预算、并行和重试限制；达到界限暂停并保存已完成工作。实际使用量与请求预留区分。子 Agent 只写隔离候选，由主任务整合；它不能代签自己的科学有效性或改变验收标准。

项目托管覆盖多个任务，但每项任务保留独立输入、目标、检查和回报。托管器根据任务图与实际产物选下一步，不因为写入新日志就建相同任务。review.withdraw 和用户暂停是控制事件而非科研建议；即使 Agent 不同意某个科学判断，也必须遵守撤回、预算与停止边界。

工坊的刺激、清洗、神经预处理、软件开发均采用相同执行入口，但各有领域适配器及检查文件。实验研究中硬件、伦理授权与实际采集由相应有权限的人或系统执行，不把工具回复当作真实实验发生。

### 领域工作不是一个通用“运行脚本”按钮

| 工坊任务 | 首个可用适配的输入/输出合同 | 必须读到的真实检查 |
|---|---|---|
| 刺激准备 | 来源图像、刺激身份、目标尺寸/呈现要求 → 刺激集、索引、预览与生成定义 | 图片实际尺寸/通道、来源映射、重复/缺失；科学变换需明确记录 |
| 图像与标注清洗 | 图像与标注表、保留/修正规则 → 派生集合、变更清单、原标注对应 | 每项标注能找到实际图像；修正可追溯，不覆盖原始输入 |
| 神经数据预处理 | 原始记录/事件/刺激/单元信息和领域约定 → 结构化派生数据、质量报告 | 时间/单元/刺激身份、形状、单位、缺失和采用范围；方法适用性另行解释 |
| 可视化工具开发 | 真实代表性结果、要完成的读图任务 → 可启动工具及可用操作 | 实际加载、选择、视图/数值隔离、保存/导出与异常输入，不只交脚手架 |
| 实验软件开发 | 经确认的实验流程、硬件/事件接口、权限 → 程序、配置、协议和验证记录 | 软件模拟测试与真实硬件验收分开；未接设备不宣称完成采集能力 |

各适配器读取项目领域约定，不把某项课题的窗口、分割、统计或数据路径硬编码为所有研究的默认。Agent 负责推荐和解释，服务器保存本任务实际采用的方法配置。

## 3.7 存储、恢复与许可边界

### 逐类真源与对账

保留可验证的既有 Store 能力，但不以 main/ 路径推断真源。每个对象声明 authority_kind；同类创建时应用同一规则。下面的表是对账依据，不能自行选择“最新时间戳胜出”。

| 对象/文件 | 权威端与外部编辑 | 保存与冲突处置 |
|---|---|---|
| notes/*.md、原生 TeX/BibTeX、分析/绘图脚本及配置 | 文件优先；允许普通编辑器修改 | 文件服务核对基础摘要，写前留恢复记录，安全替换，确认落盘后登记修订；外改按实际文件登记。与未保存缓冲冲突时保留双方，不覆盖。 |
| 主图 figure.yaml/panel.yaml、用途 variant.json 及其 overrides.json | 文件优先；主文件定义组成/继承，覆盖文件只存局部视觉值，字段不重复持有 | GUI和Agent走文件服务；多文件一次编辑有日志和完成标记，半提交不能生成。外部编辑后先校验合同，再形成可采用定义。 |
| 受管 document.json、结构化 Recipe、DatasetSnapshot、反馈、ChangeSet、任务与预算 | Store 优先；main/ 中是带摘要的交换/物化副本 | 先写不可变内容，再事务提交引用和文件同步任务；物化失败重做。外改副本作为待导入候选保存差异，不静默采用或直接覆盖回去。 |
| ProjectHead、采用关系、Delegation | Store 唯一权威 | project.yaml 仅保留身份和非权限设置；不得重复保存 adopted_refs。导出的只读状态清单有 revision，不成为第二主本。 |
| 原始数据、实际运行结果、交付快照 | 已登记的不可变对象/外部版本；不可原地编辑 | 改动另建数据/方法修订；授权销毁走 purge 例外。 |
| main/render、搜索索引、缩略图、视图状态 | 派生；视图可改，内容缓存不可编辑为真源 | 可以重建；外改生成物视为不同外来素材或污染，不倒推源内容。 |

文件优先的应用内提交使用“准备记录→核对文件→替换→登记→清理”的恢复协议。若在替换后登记前崩溃，启动对账按准备记录登记实际字节；若字节再次变化，保留快照并登记外部修改，不假装同一事务。外部进程不服从应用锁，因此不宣称任意编辑器间绝对原子 CAS。用户脚本外改是合法新方法，读取不执行；启动运行前先取得完整、已登记的文件快照。

**修订与分支。** 每个对象的提交修订线性递增，parent 是上一修订，不形成隐式 DAG。并行编辑以基于确定 base_refs 的 ChangeSet 保存；长期不同分析/表达分支创建有新身份及来源的新 Recipe/稿件对象，共享原数据。探索“方向分支”不是要求数据库修订改为分叉。CAS 冲突返回基线、当前修订和可比较差异，禁止换 latest 强重试。

**采用与成熟成果。** 未保存缓冲、已保存工作修订、待审候选、ProjectHead 采用集合、Release 分开。用户采用一个一致的修改组时，默认在同一动作内推进当前 ProjectHead；也可选择仅保留工作稿。没有额外强制“批准成熟”步骤。直接编辑已采用成果会展示工作修订及“待采用”状态，保存与采用可用一个明确组合动作；纯视图改变不进入该过程。后台默认只产候选。用户可授权特定低风险动作自动采用，并指定是否同步 ProjectHead；科学判断、范围、销毁和发布不在默认权限。Release 固定一次实际采用集合，对外发布另授权。

### 授权销毁

`data.purge.plan` 枚举受控数据、结果、缓存、修订、回收区、引用及发布包，说明跨项目使用者和无法控制的副本；`data.purge.execute` 仅接受用户显式确认的计划及范围。立即吊销访问，清除受控内容并使旧缓存失效；交付历史留下不含敏感原文的 tombstone，明确不可复现范围。独立保存的备份、已发给外部提供者/协作者的副本列出通知和确认状态，不能宣称远端已经擦除。恢复备份必须先应用销毁账本；内容寻址共享的 blob 不能因另有引用就违反已确认销毁范围。归档元数据也需检查是否含被销毁内容。物理介质安全擦除和法律适用性由相应控制方确认，不由一个 unlink 宣称完成。

### 隔离与许可

编译、脚本和外部工具按最小权限运行，无网络/无 shell-escape 为 TeX 默认，挂载仅含已登记资源。容器本身不是安全证明。运行时凭据不进入项目、笔记、图、导出或任务日志。

核心自有代码保留既有许可；不把含强 copyleft 的完整发行物宣称为纯 MIT。Tavotto 的上游许可为 AGPL-3.0-only，采用具体代码和分发方式前需保留 NOTICE、查清组合义务，并由项目所有者批准相应发行策略。[R33][R34] 同页面/不同进程都不是自动许可结论。默认只允许已授权的隔离接口评估，不把 Tavotto 代码复制进核心或打包发行。许可或接口评估失败时，自建覆盖重放层须作为有单独成本和合同的工程方案评估，不能称为无成本小修。Fidus/Overleaf 仅参考，Dockview 企业包不进入默认依赖。该唯一真正的权利人决定不能由文档伪造批准；非依赖工作可继续。

## 3.8 笔记组件与文件服务：采用一条可实施路线

**首选组合。** CodeMirror 6 负责原生文本编辑、Markdown 语言支持、选区、撤销和文内搜索；markdown-it 负责阅读渲染，DOMPurify 与资源访问策略负责展示隔离；React Arborist 负责可控树导航，Dockview 负责区域停靠。沿用已有 Python 项目服务，在其中增加 `NotebookService`，复用现有 SQLite 作可丢弃检索索引，不另引入一套笔记账号、数据库正文、同步平台或 Electron 应用。[R06][R25–R29]

Zettlr 的目录工作区、文件系统层和检索位置返回，以及 QOwnNotes 的原生 Markdown、外部修改检测和笔记导航，是业务参考；不直接嵌入它们的完整桌面程序。Milkdown 是可嵌入的可视化 Markdown 方案，但不能仅因支持 Markdown 就认为无损保存任意原文件；当前路线用 CodeMirror 保持文本权威。将来替换编辑器，必须通过同一文件保真与冲突合同，不变更笔记存储模型。[R25][R26][R31]

| 服务或组件 | 输入与职责 | 明确不承担什么 |
|---|---|---|
| NotebookService | 项目身份、受授权 notes 根目录、文件操作、内容摘要、附件与历史引用 | 不把笔记全文另存为数据库权威正文；不因 Agent 请求而扩大文件访问范围 |
| 编辑器适配器 | 文本、选区、基础摘要、显示状态；发出局部文本或保存命令 | 不直接替换磁盘文件，不在切视图时隐式转换语法 |
| 导航与链接索引 | 目录、标题、标签、普通相对链接、受管条目与反向引用 | 不移动源文件来满足一种树视图，不用标签充当项目隔离 |
| 检索服务 | 当前项目范围、文字与过滤条件；返回路径、匹配范围、摘要和索引状态 | 不将模型语义检索作为唯一入口，不把未读文件写成无结果 |
| 文件变更适配器 | 文件系统通知＋打开/检索前必要复核＋启动扫描 | 不假设文件监听无遗漏，网络卷不可用时不假装已同步 |

**检索实现。** 先保证基于实际 Markdown 的字面检索和位置定位正确，再用现有 SQLite FTS5 加速。默认 unicode 分词不作为中文子串保证；可选 trigram 索引，但少于三个字符的查询必须走明确的字面匹配/扫描路径。查询经参数化和字面转义，不能把用户输入默认当 SQL 或复杂检索表达式。索引按 project_id 与相对路径隔离，可全量重建；返回命中前确认文件修订，变化后重新定位。索引仅存派生搜索表示，不提供另一正文编辑接口。[R28]

**保存实现。** 每个受管写入带 `expected_content_sha256`。服务在适当锁与文件替换策略下检查实际内容，再落盘、确认、登记修订并更新索引。外部进程不遵守应用锁，因此不宣称能对任意外部编辑器提供分布式原子 CAS；要通过变更复核、保留修订、恢复草稿与显式冲突处理降低覆盖风险，无法排除竞态时不报告保证成立。保存失败保留编辑缓冲与可恢复草稿，项目断线只显示未同步。

**集成顺序。** W1-a 先验证两项目的原生笔记与基础文件/布局；其余笔记合同在 W1-b 补齐。W1-d 验证一个真实 Agent 工具动作，W3 再验证研究摘要和托管回报。阶段关口只按明确子断言关闭，不冒称整个 T 已通过。不得先做聊天导出，再把它冒充笔记子系统。Zettlr/QOwnNotes 的代码许可须按具体复用方式核验；仅借鉴公开行为不意味着复制实现。组件版本、许可与集成测试在实际接入时锁定，不能把本书的选择写成已验证事实。

## 3.9 最低支持面、运行形态与权限

### 运行形态和规模

首批集成采用**一个研究用户、多项目、人和多个受约束 Agent、本机 Python 服务＋浏览器工作桌**。不把多人实时共同编辑、原生桌面壳或任意 OS 的后台执行冒充首批能力；浏览器多标签仍须并发保护。服务参考环境为 Ubuntu 24.04 LTS x86-64，16 GB RAM、4 核、SSD；实际 Chromium 客户端锁定准确版本。Windows 11 的 Chrome/Edge 作为用户访问客户端在 W1-a 即检验；本机后端不承诺原生 Windows Snakemake，WSL/容器和远程 Linux 部署在 W5 分别验收。macOS/Firefox/Safari 和触摸编辑为后续平台矩阵，进入相应支持承诺前实测，不能把缩小窗口称为触摸支持。

提供一个启动命令启动服务并打开浏览器，后台是否继续须明确；默认绑定 loopback，并用用户侧引导令牌换取受保护会话。远程默认走用户授权 SSH 隧道；开放监听须 TLS、实际认证、Origin/CSRF 检查。文件选择区分客户端上传和受限服务器根目录浏览；远程 notes 位于服务器，不假装浏览器可直接写任意客户端磁盘。代码/编译依赖在一次已授权安装中准备，普通新建项目不调用模型或联网临时下载依赖。

基准工作集明确为：单稿 100 页、100 图/表引用；每图 12 个子图、5000 个可管理元素；每项目 10,000 篇笔记/100 MB 正文、20,000 个素材；数据源可引用累计 1 TB 的不可变文件，分析范围支持 1,000 万成员的分块清单。该数字是设计与验收目标，不是现有性能。超出规模不得截断或悄悄减少内容，应分页/延迟加载或明确停止并说明资源需求。TB 初次完整校验单独计量，打开项目不得强制再扫描全量源数据。

默认 TeX 工作者采用锁定的 TeX Live 发行包、latexmk/XeLaTeX/BibTeX及核明许可的中文字体，记录发行号、包/镜像摘要、字体和宏包清单；无法预先取得镜像时不得编造 digest。随包提供自有中英单栏、双栏两份基础模板，用于 T01/T15，不冒充商业期刊模板；期刊目标在授权读取当时官方要求后另建模板对象并核验再分发许可。

### 主体、预算和外发

Principal 至少区分 human_owner、agent、subagent、service、external_editor、reviewer；子主体带 parent_id，项目/对象/动作权限取父权限交集。所有作者来自认证主体，不信任请求JSON中的自报 author。当前一名研究用户可拥有多个项目；跨项目引用仍按项目授权检查。多人实时编辑不影响现在就需落实人/Agent并发和会话隔离。

人可以管理自己的反馈、采用与撤回、配置托管和授权。Agent 默认读获准材料、提出计划/候选、回复反馈、在已授权范围运行以及追加任务简报；不得删改用户意见、提升权限、改验收结果、物理销毁数据或对外发布。有限自动采用通过单独 AdoptionGrant 声明对象/动作/期限/检查，可撤销，不能从一般工具白名单推得。后台升级身份、release.create 和 purge.execute 只能由明确的人类授权触发；生成本地交付候选不等于发布。

Budget 分别计货币（币种与实际付费账户引用）、输入/输出token、CPU/GPU秒、墙钟和并行数；各约束独立累计，不假造跨模型通用token兑换。预留与实际分开，父预算覆盖子任务；请求成本无法估计时采用经用户批准的上限预留，否则暂停新增付费请求。现有授权可复用；没有明确新增费用授权时新增费用上限为零。

凭据保存在服务端用户私有配置/系统凭据服务，不在项目目录、环境快照、日志或命令回显中。DataSensitivity 为 public/internal/restricted；新科研材料默认 internal，涉及参与者隐私、伦理或协议限制的材料默认 restricted。公开文献检索可在网络白名单进行，不等于允许发送私有研究词句或整本笔记；外发授权绑定项目/素材范围、提供者、用途、期限与脱敏条件。restricted 默认不外发；导入内容、笔记和网页不得提升为权限指令。T31 检查真实服务端拒绝，而非前端隐藏按钮。

# 四、开发怎样开始、怎样持续交付

## 4.1 先验证三个会决定路线的技术问题

### 责任主体和真正的验收边界

| 责任 | 本项目默认主体 | 能做什么，不能做什么 |
|---|---|---|
| 产品/资源/发布所有者 | 当前用户 | 判断目标和体验，批准重大范围、费用、许可及发布；不承担测试编写和日常调度 |
| 实现与整合 | Codex 主会话及其实现工作树 | 写产品与开发测试、提出判据修改；不能控制最终判定环境、阈值审批和签署身份 |
| 验收维护者 | 用户指定的非实现审查会话或工程人员 | 先读需求，制定/复核公开fixture、预期、容差与留出；可由AI协助，不能只是实现会话自报换名 |
| 可信执行/判定 | 与实现凭据及工作区隔离的CI/本地受限账号 | 从保护基线加载判定器，在无签署密钥的沙箱运行候选，独立读取产物；归档/签署在另一个受保护进程 |
| 科学与体验裁决 | 用户；超出其领域时由用户指定相应人员 | 记录实物观察；模型可辅助但不冒充真实用户或人类签名 |

机器绑定存入 `spec/acceptance.yaml`；当前文档没有创建CI账号或获取用户签署，未绑定项保持 UNBOUND。缺隔离条件仍可做开发自测和提交候选，但不得标独立验收通过。相同模型可用于独立会话，真正的隔离依赖权限、输入范围与证据；不同厂商名称不是独立性证明。

**W0-A 是验收准备责任，不是实现者给自己出题。** 验收维护者在每个切片开工前批准其公開输入、可判定结果、数值容差及性能目标，建立相应判定器基线与保护规则；实现者可读公开合同并贡献候选测试，不能自批准。W0-B由实现者核现场、恢复、依赖和既有接口。W0整体关闭需二者对应的实际证据。无需在动工前建完所有领域评测系统，只需切片涉及的判据先于实现验收成立。

公开测试可读；只有有限的留出材料和答案对实现会话隐藏。候选程序执行时可能需读取测试输入，故不宣称“实现代码不能读任何fixture”；要隔离正确答案、禁止外发、限制日志回传并由独立执行器核对。签名身份或令牌绝不暴露给运行候选代码的进程。[R35]

### 三项高风险技术探针

P1：W1-b 前证明受管正文的中文IME、公式、引用、图位、批注及批量修订能从唯一来源真实编译。P2：W1-c 开工前完成 Tavotto 许可处置事件与接口探针，再验证标准图及用户脚本的热态/冷绘/重开/导出。P3：W1-d 证明固定数据、两项真实计算、结果、子图、主图与稿件沿同一计划生成。

每个探针至多两次针对同一技术假设的定向尝试；达到先登记的预算、累计4小时实际运行或第二次仍失败，任一先到即形成路线评估，不继续扩张补丁。4小时是本书建议的单次探针执行边界，不是交付工期承诺；现有更严授权优先。自建编辑引擎或自有 AgentRunner 是独立工程方案，必须先给工作分解、验证负载、投入上限再启用，不能写成一句“退路”便视为成本已覆盖。

## 4.3 每个任务都必须从需求进入代码

开发入口是 `spec/registry.yaml` 中本任务涉及的 N/T/W/C/S 与原子断言，再按记录定位正文、接口、固定来源和 fixture。注册表不是又一份需求全文：它保存追踪、状态、归属、证据位置和最后验证构建；正文保存行为解释，schema 保存机械合同，三者的映射需经校验。

```text
目标：用户在什么对象完成什么工作（N/W/T 与相关原子断言）
基线：源码/运行构建、来源快照、fixture、授权与预算
合同：接口、修改面、触及的 INV 编号、预期与拒绝条件
实现：隔离分支/工作树，候选与脚本；不写生产数据
自测：实际命令、正反例、证据 manifest、未完成项
验收：独立会话/CI在干净工作副本重放；必要人工观察另记
集成：单一负责人合并；同构建整链回归后更新验证状态
接续：通过后继续已授权工作；失败带反例修复；阻塞保留
```

实现者可以新增正常单元测试和反例。已冻结的验收标准、fixture 与判定器不得为了通过被同一实现任务自行降低；发现测试错误可提出单独的合同修正，由未实施该变更的审查者核对需求和反例。普通无范围变化的测试修正不逐次要求研究用户签字；改变产品承诺、资源或发布权限才由有权者决定。固定路径保护和 CI 权限要真正落实，不能只在提示词中宣称测试独立。

W2/W3 采用隔离 worktree 和候选目录，单一 schema/Store 写入负责人处理交叉变更。独审读取当前需求、真实构建和完整轨迹，不接受单独自报的 passed 字段；没有独立会话或重放条件时如实标识，不能代称已独立验收。代码/合同修改使用 Git 与影响记录保留历史，面向用户的产品书保持完整正文，不附版本说明或差异叙事。

## 4.4 如何控制失败与投入

没有完整运行证据的候选只标候选。连续修补没有消除同一个反例时，交付负责人重新检查接口或技术假设，不继续累积同类补丁。执行上限使用当前授权，额度不足保存状态与下一可执行任务，不重置预算、不更改通过定义。

技术路线已经给出推荐，开发端负责普通依赖和实现选择。涉及科学范围、数据迁移、不可逆操作、新费用、数据外发、许可策略或对外发布时说明影响并请求相应决定。目录、存储、协议改变先有可恢复迁移，禁止覆盖用户原始资料。

本书不是整体重写授权，也不批准删减完整产品。C01–C50 与 S01–S24 在附录 D 对应到工作包；每一项都需满足其明确条件与必要证据。先交付 W1 是工程验证与施工顺序，绝不是全产品终点。

`spec/performance.yaml` 给出默认设计目标而非实测：基准设备为3.9参考环境，热态恢复成果与笔记p95≤2秒；典型主图手势反馈≤100毫秒、最终预览p95≤2秒；10,000篇/100MB笔记的既有索引查询p95≤500毫秒（含二字中文）；局部100节点来源图p95≤1秒；100条意见的非模型提交确认p95≤1秒；冷启动至可读界面≤8秒（安装不计入但单独记录）。首次索引与TB源校验单独报告，不放入交互承诺。每项至少20次同条件测量并保留分位数、失败和实际输入。

这些是产品方在本书提出的验收目标，需在切片前由独立验收维护者核对合理性；实现方只测量和报告。达不到时优化或提交带用户影响的变更请求，不能自己放宽。具体预算/凭据、许可和CI账号没有用户提供时保留未授权/未绑定，阻止对应动作，不阻止零新增费用且已授权的独立工作。

# 五、验收：证明用户的工作完成，而不只是组件能运行

## 5.1 共同测试材料与证据

验收维护者负责公开fixture与独立判定基线，开发方可提出候选但不能自批准。组合负载包括三批身份/单位数据、排除恢复/标注更正、同形错序反例、两项职责不同的分析与一项全局拟合、结果与图的实际交接、两份用途图、中英公式引用文稿、两种模板、混合意见与两个独立notes库。先按切片提供必要部分，不要求开工前完成全部领域平台。合成材料验证软件；科研及用户价值另以授权真实材料验证。

T00–T32 及其原子断言均有明确归属、适用模式与观察对象。C/S保留完整minimum_behavior及来源；本书附录D直接展示C/S正文，原子集合在同包可读索引中展开。一个父T在部分子断言通过时保持未完成；受阻/未测/待人评不作PASS。

**证据有效性分三级。** 文件存在且哈希正确只是完整性；判定器从指定产物字段读取并比较才是行为判定；其运行基线、凭据和签署可核实才是独立验收。`check_spec.py`只做结构和引用检查，不能从manifest里的passed推出成功。判定器在受保护基线上维护，明文绑定输入fixture、目标对象/修订、产物角色/字段、比较方法与预期来源；提交一份哈希正确但对象错误或无关的产物必须失败。

证据目录 `evidence/<build>/<T>/<attempt>/` 保存构建与运行配置、fixture、规范/判定器摘要、操作轨迹、文件摘要、逐断言观察值与结论、必要人评。公开报告脱敏，敏感原件留受控地址。未实现或未绑定的判定器标NOT_IMPLEMENTED/UNBOUND，结构自检不能把它们变成产品证据。

公开fixture用于开发，W1-d/W3/W5关口各增加验收方保管的留出组合；它不引入隐藏需求。首次失败返回可定位的最小反例，必要时该反例转为公开回归并替换留出，避免“保密”阻碍修复。若真实隔离未成立，记录非独立，不能靠换会话或改报告署名冒充。

## 5.3 反向验证门槛本身

在隔离副本中移走必要产物、给入旧构建证据、让一个关键步骤失败或打断输出，门槛必须拒绝对应交付。用例不能只读取产品自己写的 passed 字段。恢复正常输入后，同一检查再通过，证明拦截来自真实条件而不是固定失败。

工程验证、工作贯通、体验和科学可信度分开判定。技术端先排除可自行发现的问题，用户再判断工作方式；不存在“用户点了同意，所以数值自动正确”。用户求助、绕行、重复输入与开发者介入应记录，不能记作独立完成。

### 半主观事项的裁决

T14 使用数据勘察、科学质疑和接续排序三个实际材料情境。领域结论至少由一位用户指定且能胜任该题的人类审查者判定（可以是本用户）；AI只辅助查证。记录依据真实性、方法适配、反例/不确定性和下一步可执行性，不设置强迫赞同或反驳的比例。T25首选行动引用的证据缺口须真实存在，先决依赖/预算/可用材料须吻合；有未解决领域争议则保留待裁决，不用多数模型投票压平。

W1内部体验由本用户实际操作三条目标任务；W3/W5涉及“支持经验有限研究者”的对外主张，至少再有一位未参与实现、经验较少的真人，不能以模型扮演。招募由用户/验收维护者安排，观察者可记录但不得替操作；开发者介入后标为经帮助完成。小样本只支持这些观察，不支持普遍人群性能结论。

阻断任务、丢修改、误把未执行当完成、越权/错误外发、看错数据范围是严重问题，单项即可不通过；迟疑但自行恢复且未误操作记录轻微问题及影响。歧义由用户与指定审查者给理由裁决，不武断以N分钟划分。证据包括知情同意范围内的操作轨迹/录屏、参与角色、任务、帮助与误解记录；身份/机密只在受控登记处保存。未取得这些观察就标PENDING_HUMAN。


## 5.4 交付物和发布条件

每个工作包交付实际可运行构建、当前使用入口、变更涉及的对象及产物、测试证据、已知限制与继续任务。最终交付包含可维护源码、锁定依赖、许可清单、安装/升级/恢复说明，以及经过验收的完整能力表。公开发布与真实数据外发另需相应授权。

成长循环使用真实失败和反馈建立回归案例；候选改进在相同输入、预算和评价条件下比较，采用有效变化并保留回退。不把多加一条提示词当成已经提高可靠性，也不为成长循环另建一个优先于科研交付的大平台。

## A.2 对外命令接口

沿用项目已有的 POST /api/action 可落地以下领域动作；动作名为本产品定义，第三方包通过适配器调用。读取接口返回对象和修订；长任务使用事件序列或可恢复轮询，不凭连接是否打开判断任务生命。

```json
{
  "action": "composition.set_slot",
  "request_id": "req-example",
  "project_id": "prj-example",
  "object_id": "paper-main",
  "expected_revision": 12,
  "payload": {
    "slot_id": "slot-figure-a",
    "asset_ref": {"id": "fig-main", "revision": 7}
  }
}
```

request_id 对相同请求去重；同一键携带不同 payload 返回冲突。expected_revision 由服务端与当前状态比较，不由模型自报通过。无权限返回拒绝，基线冲突返回可读的当前/基线信息；不能在发生冲突后强行换成 latest 重试。

## A.6 原生笔记、引用、运行与移交约定

**独立根目录。** `project.yaml` 记录 `notes_root: notes`，每个项目唯一解析；文件服务在根内处理普通文件和相对附件。项目软链接逃逸、绝对路径、远程图片和外部文档访问单独授权。远程项目的“真实文件”指其受授权存储端，网页不承诺任意本机磁盘写入；离线缓冲不是已经写入远端。

**格式与身份。** 普通笔记是 UTF-8 Markdown，无需导出、无需私有后缀；新建时可在 YAML front matter 中写最小稳定 `note_id` 与创建时间，原有未知 front matter 与正文保留。标题来自首个标题或明确元信息，文件名/显示名可变。旧 `.md` 即使没有标识也必须能读写；建立跨文件受管引用时才补身份或以不改正文的旁路映射登记，移交时映射须随包。识别出重复 id 时分辨显式独立复制与移动，不静默把不同文件合成一个对象。

**文件颗粒度。** 自由思考直接写普通正文。需被任务引用的讨论或日志条目可用稳定锚点，如 `<!-- rp-entry: entry-k7 -->`，后接可读标题和带时区时间；摘要、依据、分歧、决定与下一步使用普通 Markdown 段落/列表。任务简报增加 task_id 及实际产物引用，但不要求每一行具备结构化字段。不为每份笔记再套 `main/assets` 空壳：notes 本身有清楚目录，附件归 `notes/assets/`，科学大数据与主图仍引用已有素材，不重复复制。

**链接。** 默认使用标准相对 Markdown 链接；受管引用另保存项目/笔记/条目身份与内容摘要。显示名、编号和路径不当作唯一身份。应用内重命名先规划受影响链接，按基线更新并支持恢复；外部移动、删除、歧义重命名需要扫描与修复提示。索引可重建普通链接和标题大纲，任务历史的具体摘录与快照仍由运行记录保存，不靠“最新版”猜。

**命令面。** `notes.create/read/list/search/write/move/trash/restore/cite` 都以 project_id 定范围。写入带基础摘要，移动带源与目标及影响范围，引用带笔记修订/选区与实际摘录；每项命令返回实际路径、当前摘要、保存或冲突状态。读/查找与记入笔记不授权执行任务。前端大纲、收藏、最近打开和面板状态是可重建/可迁移的导航资料，关闭面板不改变文件。

**渲染与安全。** Markdown 阅读器不运行笔记内脚本。原始 HTML、数学、相对图片和特殊协议按支持矩阵处理，清洗、路径检查与网络访问策略同时生效。来源为检索结果、外部文件或模型输出时，同样遵守；不能把笔记中的指令提升为系统权限。

运行记录保留 plan_hash、实际环境、输入摘要、工具/脚本身份、开始结束与退出、输出摘要及检查。模型调用保留实际配置与必要工具证据，凭据不进入笔记；科研资料外发遵守授权。任务所引用的笔记内容是固定输入，后续追加简报不产生自触发循环。

移交时，notes 文件夹及相对附件可以独立阅读；完整项目额外提供跨素材引用、任务、历史与恢复说明。复制、移动、重新打开与删除重建搜索索引的测试必须成立，不能要求用户用“导出”恢复本来就应存在的 Markdown。

## B.2 可以直接拆解的五个机制

**修订采用。** Manuscripts 的 commands.ts 提供 setChangeStatuses(status, ids)，说明批量采用不必从字符串 diff 重新发明。产品在调用前固定范围与基线，调用后保存同一稿件修订，再检验 accepted 投影与真实编译。它不负责整轮反馈、批注工作流或科学判断。[R05]

**绘图覆盖。** Tavotto 的技术规则描述了完整覆盖列表、恢复缺失项、确定应用顺序、几何变化后重放及迟到响应隔离。产品应借此设定热态—冷态—重开一致性的集成测试，而不是只看画布能否拖动；项目文件身份仍由 Research Partner 管理。[R08]

**运行持久化。** Snakemake 的incomplete与执行记录供适配诊断参考；本产品跨次复用由build.plan及内容结果账本独占决策，不把本次临时工作目录的元数据当作产品缓存真源。[R09][R32]

**布局保存。** Dockview 的 panel 接口把初始化、布局、更新、序列化和焦点分开；产品保存 view_state，但 object_id 和科学内容不进入组件私有状态。UI 卸载重建不能丢当前成果或批注。[R01]

**连接验证。** React Flow 的 IsValidConnection 是判断连接的回调入口；前端可立即说明拒绝原因，后端仍要按同一 port schema 复核，保存 Recipe 后执行真实 build.plan。合法线条不是已运行证据。[R03]

## B.3 维护、许可与替换规则

W0 为采用包生成依赖锁、来源提交、许可/NOTICE、必要补丁和测试入口。需要打补丁时维护小型适配层或清楚的上游补丁，不能复制整仓后失去升级能力。对只读了 README 的项目不写“源码已审计”；对项目自己的测试宣称不写“本产品已验证”。

# 附录 C：一条用于开工的真实链路

## C.1 固定输入与可观察目标

各链均在同一项目通过真实界面和服务完成，不能直接改库填成功。用例编号、适用模式、必需原子集合见milestones及可读索引。生成链、科研价值和全产品分别验收。

`spec/contracts/` 是请求/响应、数据范围、用途图、反馈轮次和证据清单的 JSON Schema；`spec/examples/` 有明确合成的正反例。`tools/check_spec.py` 与 `tests/test_spec_tools.py` 只检验合同和追踪工具，不声称运行了 Research Partner 的产品测试。

`spec/adapters.yaml`、`spec/performance.yaml` 和 `spec/decision_protocol.md` 保存提供者退路、性能关口、验收权限与规范变更规程。工程历史由 Git 与具名影响记录保留；产品书本身只呈现当前完整设计。留出验收由独立验收方在真实隔离条件下另建，本包不提供虚假的“密封成功”声明。

开发团队可以扩展单元测试；改变已冻结验收语义或fixture必须独立审查和重映射。任何降低承诺需得到有权者批准；普通实现修正由工程端自主进行。完整说明见同包《开发执行协议》。


`spec/architecture.yaml`、`spec/permissions.yaml`和`spec/acceptance.yaml`分别给出架构裁决、服务端权限与真实验收主体绑定。`spec/milestones.yaml`将每个关口展开为确切的原子断言＋编辑模式，`spec/evidence_bindings.yaml`规定每项观察对象与依据；没有实际判定器时路径为空且保持未实现。结构校验绝不伪装独立产品执行。
