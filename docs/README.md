## 维护方式

- 词义改在领域词表；产品设计约束改在产品上下文；视觉令牌改在设计规范与正式样式源码；已接入行为改在相应架构记录和使用指南。
- 提案、需求、实现与验收范围分开记录。保留已有需求和验收编号；方案变化应写明依据与影响，不能通过目录整理删减要求。
- 每个主题维护一份当前正文；被替代的界面、文档和原型从工作树移除，历史通过 Git 追溯。
- 源码、测试夹具和文档引用一起移动。截图、日志及本机验收输出放入忽略的 `.private/`；可复现命令和长期结论写入对应文档。
- 原始输入保留在 `docs/plan/`：[产品企划书](plan/AcaPartner_科研AI原生产品创业企划书_v0.1.docx)、[科研基本功](plan/科研基本功_五层十八式与真传_初稿.docx)。保留原件与来源，不作为当前功能已完成的依据。

本索引面向完整源码仓库。发行包仍受 `tools/build.py` 的公开文件清单约束；原始输入和本机验收档案不随包发布，新增文档与源码入口的发行范围须在打包时单独核对。
